# 이벤트 리서치 & 옵시디언 방향성 논의 — 결정사항

## 결정사항

### 이벤트 리서치 (enrich)
1. 검증 순서는 **기존 이벤트 → draft 이벤트** 순으로 enrich를 돌려 정보를 채운다. discover로 새로 찾는 게 아니라, 모든 이벤트에 소스가 있어야 비교가 유의미하기 때문.
2. **슬랙 실제 반영 + 알림 테스트는 draft 이벤트로 진행한다.** draft는 아직 배포되지 않았으므로 정보가 채워지면 바로 반영하고 슬랙 알림이 와도 된다.
3. 김규형이 검증 완료 목록을 전달하면 **이준범이 draft → publish로 전환**한다.
4. **TC를 별도 문서로 작성한다.** 지금 있는 것은 검증 항목 목록일 뿐이므로, T0/T0-1/T0-2 식 케이스 번호와 통과 판정이 가능한 형태로 만든다. 기존 목록을 그대로 클로드에 넣어 생성하고, 결과는 이준범이 검토한다.
5. **완성도 100%의 기준은 "공식 사이트를 잘 긁어오는 것"까지**로 정의한다. 기사·블로그·인스타 등 비공식 소스 확장은 그 이후. 이 기준에서 현재 약 90%.
6. **긴 이미지 페이지는 비전 이미지 분할 방식으로 처리한다.** 비용이 2배가 되지만 케이스당 $5 이내이므로 감수하기로 함.
7. **새벽 배치로 하루 약 50개씩 돌리는 운영을 승인.** 미래 대회 300개 남짓 / 쿨타임 7일 기준. Max 플랜 토큰 한도 내에서 커버 가능하다고 판단.
8. 검수 방식: 이준범이 **랜덤 이벤트 약 10개**를 던져 enrich를 돌리게 하고, 슬랙 알림 내용과 실제 사이트를 직접 대조한다. 일정은 **2026-08-04(화) 점심 직전 실행, 점심 후 결과 확인**.

### 옵시디언
9. **모두가 옵시디언을 다이렉트로 쓴다.** 세일즈=노션 / 개발=깃으로 팀별 입력 통로를 나누는 안은 폐기. 옵시디언 도입 시 노션은 아예 쓰지 않는 방향.
10. **동기화는 깃 방향으로 간다.** 단, 비개발자가 커밋/PR/푸시 개념 없이 쓸 수 있도록 **"다 썼으니 넘겨줘" 한 마디로 PR 생성 → 머지 → 풀까지 자동 수행하는 스킬**을 만드는 것을 전제로 한다.
11. **레포는 모노레포와 분리해 옵시디언 전용 위키 레포를 둔다.** 비개발자는 모노레포를 볼 필요 없이 이 레포만 바라본다. 원본은 맥미니에서 관리.
12. **회의록 등 문서 생성은 슬랙 플러그인 경유가 아니라 오르카 + 클로드 직접 방식**으로 간다. 텍스트를 그대로 올리고 "이거 넘겨달라"고 하면 템플릿에 맞춰 변환·저장되는 흐름이 더 빠르다고 판단.
13. 역할 구분: **옵시디언 = 메모리, 헤르메스 에이전트 = CPU.** 오르카가 팔다리로 정보를 수집·생성하고, 헤르메스는 결정사항 등 정말 필요할 때만 뇌 역할을 한다.
14. 파일 구조는 현재의 카파시(Andrej Karpathy) 위키 구조를 그대로 유지한다 (이준범 "좋은 것 같다").

## 미결정 / 보류
- 옵시디언 Sync 유료 결제 여부 — 쓸 가치가 있으면 쓰되 **연간 결제는 하지 않는다**는 선까지만 정해짐 (1년 내 유행이 지날 수 있다는 이유).
- 깃 + 자동화 스킬 방향은 "이 방향으로 다시 디벨롭해 보자" 단계이며 최종 확정은 아님.
- 슬랙 → 옵시디언 플러그인 채택 여부 — 오르카 직접 방식으로 기울며 후순위가 됐으나 명시적으로 폐기하지는 않음.
- enrich 스킬 이후의 후속 작업 계획 — 2026-08-04에 다시 논의.
- 소규모 대회(공식 SNS 없이 블로그/카페만 있는 경우)의 스폰서 정보 수집 — 후순위로 보류.
