# lint 규칙

260811 싱크에서 정한 세 오퍼레이션(ingest / query / **lint**) 중 lint 다.
사서(Hermes)가 주기적으로 서가를 점검하는 일에 해당한다.

```
매주 월요일 09:30  →  vault/log/lint-report.md 갱신
```

**직접 돌려보기**
```bash
python3 .automation/wiki_lint.py            # 전체
python3 .automation/wiki_lint.py --rule L2  # 규칙 하나만
```

---

## 0. 고치지는 않는다

**이 도구는 찾아서 보고만 한다.** 자동 수정을 넣지 않은 이유는 사람이 의도해서 만든
예외를 지워버릴 수 있기 때문이다. 무엇이 어긋났는지 목록만 내고, 고칠지는 사람이 정한다.

---

## 1. 규칙 7개

| | 규칙 | 왜 필요한가 |
|---|---|---|
| **L1** | 깨진 위키링크가 없을 것 | 링크가 끊기면 맥락 추적이 끊긴다 |
| **L2** | 번호 표기가 태그로 오인식되지 않을 것 | 태그 창이 `#9는` 같은 쓰레기로 찬다 |
| **L3** | 모든 문서에 `created` 가 있을 것 | 언제 것인지 모르면 최신 여부를 못 판단한다 |
| **L4** | 아무도 링크하지 않는 문서가 없을 것 | 검색으로만 닿는 문서는 묻힌다 |
| **L5** | 고쳐진 문서에는 `updated` 가 있을 것 | git 이력과 대조해 판정 |
| **L6** | `raw/` 원본이 사후에 수정되지 않았을 것 | 원본이 바뀌면 근거가 사라진다 |
| **L7** | `review_by` 가 지난 문서 보고 | 오래된 문서 정리 장치 |

## 2. 규칙별 대응 방법

### L1 — 깨진 위키링크
가리키는 파일이 없다. 셋 중 하나다.
1. 파일명이 바뀌었다 → 링크를 새 이름으로
2. 아직 안 만든 문서다 → 만들거나 링크를 지운다
3. **예시로 쓴 표기다** → 백틱으로 감싼다 (`` `[[예시]]` ``)

### L2 — 번호 표기가 태그로
`결정 #12가` 처럼 쓰면 `#12가` 라는 태그가 생긴다. 백틱으로 감싼다: `` 결정 `#12`가 ``
자세한 배경은 [[링크-규칙]] §5.

### L3 — `created` 누락
프론트매터 맨 위에 `created: YYYY-MM-DD` 를 넣는다. 언제인지 모르겠으면
`git log --format=%ad --date=short -- <파일>` 의 마지막 줄이 최초 커밋일이다.

### L4 — 고아 문서
어느 문서에서도 링크되지 않았다. 관련 허브에서 걸어준다 ([[링크-규칙]] §3).
`raw/` 는 자동 수집 영역이라 검사에서 제외한다.

### L5 — `updated` 가 없거나 낡음
git 상 두 번 이상 커밋된 문서인데 `updated` 가 없거나 마지막 커밋보다 옛날이다.
**한 번 쓰고 안 고친 문서는 걸리지 않는다.**

### L6 — raw 원본이 수정됨
`raw/` 파일을 건드린 커밋이 2개 이상이다. **오탈자라도 원본은 고치지 않는다** —
교정은 정리본에 적는다 ([[폴더-규칙]] §2). 이미 고쳤다면 되돌리고 wiki 쪽에 반영한다.

### L7 — 검토 기한 경과
`review_by` 날짜가 지났다. 확인해서 (a) 아직 맞으면 날짜를 미루고
(b) 틀렸으면 고치고 (c) 더 이상 안 쓰면 `#폐기` 를 붙인다.

## 3. 첫 실행 결과 (2026-08-12)

규칙을 상상해서 만든 게 아니라 **실측에서 나온 것들**이다.

| | 발견 | 조치 |
|---|---|---|
| L1 | 2건 | 예시 표기 백틱 처리 / `raw/slack` 안내 문서 신설 |
| L2 | 14건 | `#9는` → `` `#9`는 `` (의미 보존, 태그 등록만 차단) |
| L3 | 11건 | git 최초 커밋일로 백필 |
| L5 | 7건 | git 최종 커밋일로 백필 |
| L4 | 2건 | [[repo-map]] 에 인덱스 추가 |

**60건 → 0건.**

> 이때 배운 것: L3 위반 대부분의 원인은 사람이 아니라 **[[템플릿-가이드]]에
> 프론트매터 규격이 아예 없던 것**이었다. 생성기가 규격을 모르면 산출물 전체가
> 같은 위반을 갖는다. **lint 가 진짜로 알려주는 것은 개별 문서의 흠이 아니라
> schema 의 구멍이다.**

## 3-2. 후보 규칙 (미구현)

### L8 — `schema/` 가 바뀌었는데 `CLAUDE.md` 가 안 바뀜

에이전트가 실제로 로드하는 건 레포 루트 `CLAUDE.md` 이고, `vault/schema/` 는 그
정본이다([[폴더-규칙]] 경고 블록). **둘을 따로 관리하므로 갈라지기 쉽다.**

검사 방법은 단순하다 — 최근 커밋에서 `vault/schema/` 가 바뀐 이력이 있는데
같은 커밋에 `CLAUDE.md` 가 없으면 보고한다.

```bash
git log --format=%H -1 -- vault/schema/   # schema 를 마지막으로 바꾼 커밋
git show --name-only <그 커밋> | grep -q '^CLAUDE.md$'
```

**아직 안 넣은 이유**: 규칙 전문이 바뀌었다고 요약본까지 반드시 바꿔야 하는 건
아니다(오탈자 수정 등). 오탐이 많으면 §4 의 세 번째 기준("사람이 고칠 수 있는가")에
걸린다. 실제로 갈라지는 사고가 한 번 나면 그때 넣는다.

## 4. 규칙을 바꾸려면

규칙 정의는 `.automation/wiki_lint.py` 의 `RULES` 에 있고, **이 문서가 정본이다.**
바꿀 때는 둘 다 고친다. 규칙이 에이전트 동작에 영향을 준다면 `/CLAUDE.md` 도 함께 —
이유는 [[폴더-규칙]] 의 경고 블록 참조.

새 규칙을 넣을 때 기준:

1. **실제로 발생한 문제인가** — 가상의 위험 말고
2. **위반이 전체의 절반을 넘지 않는가** — 넘으면 규칙이 틀린 것이다
3. **사람이 고칠 수 있는가** — 고칠 방법이 없는 지적은 소음이다
