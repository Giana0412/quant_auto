# 카파시 원문 대조

260803 결정 14번이 *"카파시 위키 구조를 채택한다"* 인데, **그 근거 문서가 지금까지
vault 에 없었다.** 2026-08-12 에 원문을 받아 [[karpathy-llm-wiki]] 로 보존하고
현재 구현과 대조했다.

> 260811 싱크에서 이준범이 *"앤드리 카파시가 제시한 LLM 위키에 그게 다 나와 있어요"*
> (34:38) 라고 한 그 문서다. **읽지 않고 자체 설계한 것이 이번 격차의 근본 원인이다.**

---

## 0. 한 줄 요약

**층 구조는 맞췄지만, 그 위에서 도는 동작을 절반만 만들었다.**
카파시 위키의 핵심은 폴더가 아니라 **"새 자료가 들어올 때마다 기존 문서들이 갱신되는 것"**
인데, 우리 ingest 는 새 문서 3개를 만들고 끝난다.

---

## 1. 맞게 간 것

| 원문 | 우리 |
|---|---|
| **Raw sources** — *"These are immutable — the LLM reads from them but never modifies them"* | ✅ `raw/` + lint L6 이 사후 수정을 감시 |
| 3층 (raw / wiki / schema) | ✅ 5층으로 구현 (+index, +log — 원문도 이 둘을 별도 절로 다룬다) |
| *"The wiki is just a git repo of markdown files"* | ✅ |
| *"Obsidian is the IDE; the LLM is the programmer"* | ✅ 사람은 Orca+Claude 로 시키고 Obsidian 은 읽는 창 |
| index.md / log.md 를 둔다 | 🟡 만들었으나 내용이 원문과 다름 (§2-6, §2-7) |

---

## 2. 놓친 것

### 2-1. 🔴 ingest 가 **기존 문서를 갱신하지 않는다** — 가장 큰 격차

> **원문**: the LLM reads the source, (…) writes a summary page in the wiki, **updates the
> index, updates relevant entity and concept pages across the wiki**, and appends an entry
> to the log. **A single source might touch 10-15 wiki pages.**

우리 ingest 는 전사본·정리본·결정사항 **3개를 새로 만들고 끝난다.** 기존 문서는
하나도 안 건드린다.

```
카파시           새 자료 1개  →  10~15개 문서가 갱신됨 (누적)
우리             새 자료 1개  →   3개 문서가 새로 생김 (병렬)
```

**이게 "왜 이렇게 링크가 적어요?"(25:28) 의 답이다.** 이준범 위키는 167노드/530엣지인데,
매 ingest 마다 새 내용이 기존 페이지들로 짜여 들어가기 때문이다. 우리는 고립된
3종 세트가 계속 쌓이기만 한다.

원문이 말하는 핵심도 정확히 이것이다.

> The knowledge is **compiled once and then kept current**, not re-derived on every query.
> (…) the wiki is a **persistent, compounding artifact**.

### 2-2. 🔴 엔티티·개념 페이지가 **아예 없다**

> **원문**: Summaries, **entity pages, concept pages, comparisons, an overview, a synthesis**

우리 `wiki/` 에 있는 건 **회의 기록과 설계 문서**뿐이다. 주제별·인물별·파트너별
페이지가 없다.

그래서 *"채널A 와의 딜이 어떻게 됐지?"* 를 물으면 회의록 5개를 뒤져야 한다.
카파시 방식이면 `채널A.md` 한 장이 이미 최신 상태로 있어야 한다.

**2-1 과 같은 뿌리다.** 갱신할 엔티티 페이지가 없으니 ingest 가 갱신할 것도 없다.

### 2-3. 🔴 lint 가 **기계 검사만** 한다

> **원문**: Look for: **contradictions between pages**, **stale claims that newer sources
> have superseded**, orphan pages with no inbound links, **important concepts mentioned but
> lacking their own page**, **missing cross-references**, data gaps (…) The LLM is good at
> **suggesting new questions to investigate**.

원문의 lint 항목 6가지 중 우리가 하는 건 **고아 페이지 하나**뿐이다.

| 원문 항목 | 우리 |
|---|---|
| 문서 간 모순 | ❌ |
| 새 자료가 뒤집은 낡은 주장 | ❌ |
| 고아 페이지 | ✅ L4 |
| 언급만 되고 페이지가 없는 개념 | ❌ |
| 빠진 상호참조 | ❌ |
| 채워야 할 데이터 공백 | ❌ |
| 새로 파볼 질문 제안 | ❌ |

나머지 6개는 **의미를 봐야 해서 스크립트로는 못 한다 — LLM 이 해야 한다.**
원문도 *"ask the LLM to health-check"* 라고 쓴다.

이준범이 *"린트는 자동으로 정화가 돼야 돼요… 연결이 되고 통합이 되고 통폐합이 되고,
이게 LLM 위키의 핵심이에요"*(33:07) 라고 한 게 이 부분이다.

> 우리 lint(L1~L7)가 쓸모없다는 뜻은 아니다. 60건을 잡아 고쳤고 지금도 매주 돈다.
> 다만 **그건 문법 검사이고, 원문이 말하는 lint 는 건강 검진이다.**
> 이름을 같이 쓴 탓에 "lint 완료"로 보고한 것이 과했다.

### 2-4. 🔴 query 결과가 **위키로 돌아오지 않는다**

> **원문**: **good answers can be filed back into the wiki as new pages.** A comparison you
> asked for, an analysis, a connection you discovered — these are **valuable and shouldn't
> disappear into chat history.** This way your explorations compound.

우리 `ask` 스킬은 **읽기 전용**으로 못박아 놨다. 좋은 답도 대화창에서 사라진다.
원문이 말하는 **복리(compounding)** 고리가 끊겨 있다.

### 2-5. 🔴 schema 가 **에이전트가 읽는 파일이 아니다**

> **원문**: The schema — **a document (e.g. CLAUDE.md for Claude Code or AGENTS.md for Codex)
> that tells the LLM how the wiki is structured** (…) **This is the key configuration file —
> it's what makes the LLM a disciplined wiki maintainer rather than a generic chatbot.**

우리 `schema/` 문서 7개 중 **에이전트가 실제로 읽는 건 `템플릿-가이드.md` 하나**다
(ingest 프롬프트가 첫 줄에서 읽는다). 나머지 6개는 **사람이 읽는 문서**이고
어떤 자동화도 로드하지 않는다.

**이준범이 "우리가 이런 규칙을 제안을 하는 게 아니라 [에이전트가] 알아서 태그를 하고
알아서 링크를 하게끔 만들어야 돼요"(34:22) 라고 한 게 이 지점이다.**

규칙을 없애라는 뜻이 아니라, **규칙을 사람이 지키는 문서가 아니라 에이전트가 로드하는
설정으로 만들라**는 뜻으로 읽는 게 원문과 맞다. 카파시의 schema 는 그 자체가 CLAUDE.md 다.

### 2-6. 🟡 log 가 append-only 작업 기록이 아니다

> **원문**: **append-only** record of what happened and when — **ingests, queries, lint passes.**
> 각 항목을 `## [2026-04-02] ingest | Article Title` 처럼 시작하면
> `grep "^## \[" log.md | tail -5` 로 최근 5건을 뽑을 수 있다.

우리 `log/` 는 `session-log.md`(사람이 손으로 씀) + `lint-report.md`(매번 덮어씀)다.
**ingest 도 query 도 로그가 없다.** 무엇이 언제 위키에 들어왔는지 추적이 안 된다.

§5-1 에서 제안한 "조회율 측정"도 사실 이 log 가 있으면 자연히 된다.

### 2-7. 🟡 index 에 한 줄 요약이 없다

> **원문**: each page listed with a link, **a one-line summary**, and optionally metadata

우리 `index/문서지도.md` 는 이름만 나열한다. 요약이 없으면 **에이전트가 인덱스만 보고
어느 페이지를 열지 판단할 수 없어** 결국 다 열어봐야 한다. 원문이 인덱스를
*"RAG 인프라 없이도 통하는"* 장치라고 한 이유가 그 한 줄 요약에 있다.

되니까"*(34:04) 라고 했으므로 **합의 전에 구현하지 않는다.** 무엇을 이야기해야 하는지만 적는다.

| 2 | 엔티티·개념 페이지 도입 (§2-2) | 큼 — 무엇을 엔티티로 볼지부터 | ⏸️ 합의 대기 |
| 3 | LLM lint 추가 (§2-3) | 중 | ⏸️ 합의 대기 |
| 4 | ask 결과를 위키로 회수 (§2-4) | 중 | ⏸️ 합의 대기 |
| 5 | schema 를 에이전트가 로드하게 (§2-5) | 작음 | ✅ **2026-08-12 완료** |
| 6 | log 를 append-only 기록으로 (§2-6) | 작음 | ✅ **2026-08-12 완료** |
| 7 | index 에 한 줄 요약 (§2-7) | 작음 | ✅ **2026-08-12 완료** |

**1·2·3·4 는 위키의 성격을 바꾸는 일이라 합의가 먼저다** —
이준범이 *"구조 같은 거는 제가 나중에 잡으면 되니까"*(34:04) 라고 했다.

### 5·6·7 로 무엇이 바뀌었나

| | 무엇을 했나 | 검증 |
|---|---|---|
| **5** | 레포 루트에 `CLAUDE.md` 신설 — 층 권한·프론트매터·링크·판정 규칙을 담고 schema 원문으로 연결. 헤드리스 `claude -p` 는 cwd 가 레포 루트라 자동 로드된다 | 파일 읽기 도구 없이 *"raw 를 고쳐도 되나"* 를 물어 **정확히 답하는 것 확인** |
| **6** | `vault/log/log.md` 신설. 형식은 원문 그대로 `## [날짜] op \| 대상`. ingest·lint 가 자동 기록, `ask` 스킬은 조회를 기록 | `grep -c '^## \[.*\] query '` 로 **조회 횟수가 실제로 세어짐** |
| **7** | `index/문서지도.md` 의 모든 항목에 한 줄 요약. `purpose` 우선, 없으면 본문 첫 문장, 그것도 없으면 목록 첫 항목 | 63/63 항목에 요약 부착 |

**6번이 §5-1 의 "조회율 측정 수단 없음"을 해결한다.** 그리고 `--no-found` 로 남는
못 찾은 질문 목록이 곧 **다음에 채울 곳**이 된다.

## 5. 배운 것 — 정리본만 보면 이렇게 된다

이 대조는 **전사본을 읽고 나서야** 가능했다. 정리본은 lint 를 *"주기적인 lint 수행으로
중복 제거, 위치 재배치, 구조 정비"* 라고만 적었고, **"이게 LLM 위키의 핵심"** 이라는
강조와 자동 정화 요구가 빠졌다. 슬랙 경로에 대한 의문도 *"중심축은 아님"* 으로 약해졌다.

**전사본을 `raw/` 에 원문 그대로 보존하는 규칙([[폴더-규칙]] §2)의 근거가 이것이다.**
그 규칙을 만든 당일에 정작 나는 전사본 없이 일했다.
