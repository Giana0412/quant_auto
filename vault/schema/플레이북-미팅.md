# 플레이북 — 미팅

> **이 문서는 "우리가 뭘 정했나"가 아니라 "이 일을 어떻게 하나"를 적은 것이다.**
> 260811 싱크에서 이준범이 말한 *"미팅을 할 때는 이렇게 해야 된다라고 책에 적혀
> 있어요"*(57:31) 의 그 책이다. 사람도 읽고 **에이전트도 읽는다.**

---

## 0. 한 장 요약

```
회의 끝남
   │
   │ ① 사람: 전사본을 받아서 "이거 정리해줘"
   ▼
raw/transcripts/          원본. 이후 아무도 고치지 않는다
   │
   │ ② 에이전트: ingest
   ▼
wiki/05-meetings/         정리본(이해) + 결정사항(실행)
   │
   │ ③ 자동
   ▼
index/할일.md             담당자별 할 일
index/회의.md             3종이 갖춰졌는지
log/log.md                무엇이 언제 들어왔는지
```

**사람이 하는 건 ①뿐이다.** 나머지는 자동으로 따라온다.

---

## 1. 회의가 끝나면 — 사람이 하는 것

### 1-1. 전사본을 확보한다

ClovaNote 등으로 받은 `.txt` 를 준비한다. **요약본 말고 전사본 원문**이다.

> **왜 원문인가.** 요약본만 남기면 나중에 "그 사람이 정말 그렇게 말했나"를 확인할
> 수 없다. 실제로 2026-08-11 회의는 정리본만 보고 작업했다가 핵심 지시를 놓쳤고,
> 전사본을 읽고 나서야 바로잡았다.

### 1-2. Orca 에서 Claude 에게 넘긴다

```
"이 회의 전사본 정리해줘"        ← handoff 스킬이 받는다
```

파일을 그대로 붙여넣거나 경로를 알려주면 된다.
**슬랙에 올릴 필요 없다.** 각자 자기 Orca 에서 직접 넣는 것이 기본 경로다.

> 슬랙 채널(`#test_ob`)로도 들어온다. 그건 **보조 통로**이지 유일한 입구가 아니다.
> 회의를 한 사람이 자기 자리에서 바로 넣는 것이 가장 짧다.

### 1-3. 사람이 하지 않는 것

| | 왜 |
|---|---|
| 3종 문서를 손으로 쓰기 | 에이전트가 템플릿대로 만든다 |
| 파일명 정하기 | 규칙이 있다 ([[폴더-규칙]] §6) |
| 링크 걸기 | 에이전트가 건다 |
| `raw/` 원본 고치기 | **절대 금지.** 오탈자도 정리본에서 바로잡는다 |

## 2. 에이전트가 하는 것 — ingest

전사본을 받으면 **[[템플릿-가이드]] 를 먼저 읽고** 그 형식대로 3종을 만든다.

| 문서 | 어디에 | 성격 |
|---|---|---|
| 전사본 | `raw/transcripts/` | **보존** — 원문 그대로, 요약 금지 |
| 정리본 | `wiki/05-meetings/정리본/` | **이해** — 한줄요약·핵심논의·맥락·미결·액션 |
| 결정사항 | `wiki/05-meetings/결정사항/` | **실행** — 결정·보류·액션아이템 |

파일명은 `YYMMDD-주제-{전사본,정리본,결정사항}.md`.

### 정리본에서 반드시 지킬 것

- **반대 의견과 폐기된 대안을 남긴다.** 결론만 적으면 "왜 그렇게 정했는지"가 사라진다
- 전사 오기가 있으면 하단에 교정 내역을 적는다 (원문은 그대로 둔다)
- 미결정 사항은 **누가 정할지까지** 적는다

### 결정사항의 액션 아이템 형식 — 이건 지켜야 한다

`index/할일.md` 가 이 형식을 파싱한다. 어긋나면 담당자별 할 일에 안 잡힌다.

```md
## 액션 아이템

**김규형**
- 할 일 내용 — 기한이 있으면 여기에
- 다음 할 일

**박지호**
- ...
```

담당자가 한 명뿐이면 인라인도 된다: `- [김규형] 할 일 내용`

## 3. 자동으로 따라오는 것

ingest 가 끝나면 스크립트가 이어서 돈다. **사람이 부르지 않아도 된다.**

| | 무엇 | 결과 |
|---|---|---|
| `wiki_todo.py` | 결정사항의 액션아이템을 담당자별로 | [[할일]] |
| `wiki_index.py` | 회의 목차·문서 지도 갱신 | [[회의]] · [[문서지도]] |
| `wiki_log.py` | 무엇이 언제 들어왔는지 | `log/log.md` |

**[[회의]] 목차는 3종 중 빠진 게 있으면 표시한다.** 정리본만 있고 전사본이 없으면
"전사본 없음"으로 뜬다 — 원본 없이 만든 문서라는 뜻이라 근거를 못 찾을 수 있다.

---

## 4. 액션 아이템이 각자에게 닿는 길

> 260811 싱크: *"주간에 미팅을 하면 무슨 일을 할지가 결론이 나잖아요. 대부분의
> '내가 뭘 해야겠다'는 것도 미팅으로서 정립이 되고, **그게 본인의 데일리에
> 반영되는 어떤 스킬**"* (1:05:28)

```
결정사항의 액션 아이템
   │
   ├─▶ index/할일.md          담당자별로 모임. 회의 날짜·출처 문서 링크 포함
   │
   └─▶ (STAGE2, 현재 꺼둠)
        Slack 에 기한 문의 → 답장 파싱 → 캘린더 등록 → 당일 알림
```

**아침에 볼 곳은 [[할일]] 하나다.** 회의록을 하나씩 열 필요 없다.

> STAGE2 는 **의도적으로 꺼져 있다.** 밀린 결정사항이 한꺼번에 Slack 에 게시되는 것을
> 막기 위해서다. 켜려면 `process-slack-docs.sh` 의 `STAGE2_ENABLED=true`.

## 5. 잘 됐는지 확인하는 법

```bash
python3 .automation/wiki_lint.py          # 규칙 위반 (링크·프론트매터·원본 훼손)
grep '^## \[' vault/log/log.md | tail -5  # 최근 작업 이력
```

그리고 [[회의]] 목차에서 **3종이 다 ✔ 인지** 본다.

## 6. 아직 안 되는 것

정직하게 적는다. 물어보면 답이 없다는 뜻이다.

| | 상태 |
|---|---|
| 회의 내용이 **기존 문서에 반영되는 것** | ❌ 새 문서 3개만 만들고 기존 페이지는 안 건드린다 ([[카파시-원문-대조]] §2-1) |
| 파트너·주제별 페이지 갱신 | ❌ 그런 페이지가 아직 없다 |
| 할 일 완료 표시 | ❌ 결정사항 문서를 고쳐야 한다 |
| 회의에서 안 나온 개인 할 일 | ❌ 들어갈 곳이 없다 |
