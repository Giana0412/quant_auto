# 파이프라인 설계 근거

실행법은 `README.md`, 코드 세부는 각 파일 docstring.
여기는 **"왜 이 선택이었나"와 "무엇을 포기했나"**만 남긴다.

## 두 개의 렌즈
| | 수비형 `market_metrics.py` | 공격형 `momentum_screen.py` |
|---|---|---|
| 랭킹 | 초과수익 ÷ 변동성^0.5 | 모멘텀·거래량·**변동성 가점**·신고가 |
| 상관 | 0.75 초과 제외 | **안 거름** (몰리는 게 목적) |
| 배분 | 역변동성 | **정변동성** |
| 종목 | 6개 | 4개 |

**왜 둘인가** — 대회 페이오프가 콜옵션이라 수비형 목적함수가 반대 방향이다.
그렇다고 버리지 않은 것도 교수 A 조언이다. → `advice/` (로컬 전용)

## 검증이 원리상 불가능한 부분
유니버스를 **오늘 시점 ETF 보유종목**에서 만든다 → 생존편향 → **개별종목 스크리닝은
백테스트가 불가능하다.** 그룹 ETF 로테이션만 검증 가능하고, 그마저 F-2 처럼 노이즈다.

**→ 그래서 `paper_track.py` 를 만들었다.** 오늘부터 매일 북을 기록하면 대회 시작 시점에
3주치 **진짜 OOS 기록**이 생긴다. 편향 없는 숫자를 얻을 유일한 경로다.

## 근거가 약한 채로 둔 값 — 정직하게 남긴다
| 값 | 현재 | 근거 |
|---|---|---|
| `VOL_PENALTY` | 0.5 | ⚠️ **백테스트로 못 골랐다.** 설계 의도 (→ C-3) |
| `momentum_screen` 가중치 | 35/30/20/15 | ⚠️ **검증 불가.** 표본 없음 + 생존편향 |
| `SECTOR_RULES` 목표·손절 | 섹터별 상이 | ⚠️ 회의의 **질적** 근거를 옮긴 출발점 |
| `MIN_SPAN21` | 5% | ✅ 회의 문장을 그대로 옮김 + 실측 뒷받침 |

**규율**: 숫자를 바꿔가며 "좋아 보이는" 걸 고르면 그게 과적합이다. 실제로 한 번 밟았다(C-3).

## 스스로 속지 않기 위한 장치
브리핑이 매일 자기를 경고한다 — 추격매수(RSI 과열) · 상관 0.99 착시 ·
표본내 편향 · 백테스트 노이즈 · **"뉴스 없음"은 중립이 아니라 모름**.

> 교수 B 본인이 코스피 리포트 텍스트마이닝으로 롱온리 시그널을 만들어봤으나
> **컨센서스 대비 초과성과가 안 나왔다**고 했다. 우리 `news_sentiment.py` 기대치를
> 그만큼 낮춰 잡아야 한다.

## 반복해서 밟은 함정
| | 무엇 | 어떻게 막았나 |
|---|---|---|
| 🔴 | 프롬프트 안 큰따옴표 → 문자열 절단 | `check_prompts.py` (이번에 또 잡힘) |
| 🔴 | 같은 날짜 이벤트 둘 → `sorted()` 가 dict 비교 → 브리핑 전체 사망 | `key=` 지정 |
| 🔴 | `BENCH` 는 **표시용 라벨**이지 티커가 아님 | `BENCH_TICKER` 분리 |
| 🔴 | 역변동성 목표합 `cap×n` → n=6 에서 **비중 108%** (레버리지, 규정 위반) | `min(1.0, cap×n)` |
| 🔴 | 보조 절이 늦어 **본체 파일이 안 써짐** | 스크립트 자체 상한 + 프롬프트에 "무조건 파일 작성 도달" |
| ⚠️ | 노트북 절전 → `timeout` 이 벽시계를 세어 오작동 | 미해결. 상한 상향으로는 못 막는다 |
