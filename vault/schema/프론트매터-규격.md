# 프론트매터 규격

문서 맨 위 `---` 사이에 들어가는 부분이다. Obsidian 이 이걸 읽어 검색·정렬에 쓰고,
에이전트도 "이게 언제 것인지, 누구에게 물어야 하는지"를 여기서 판단한다.

```yaml
---
created: 2026-08-12
updated: 2026-08-12
owner: 김규형
purpose: 이 문서가 무엇인지 한 줄
---
```

---

## 1. 키 목록

| 키 | 필수 | 형식 | 뜻 |
|---|---|---|---|
| `created` | **필수** | `YYYY-MM-DD` | 문서를 **만든 날**. 회의한 날이 아니다 |
| `updated` | 고쳤으면 필수 | `YYYY-MM-DD` | 마지막으로 고친 날 |
| `owner` | 권장 | 이름 | 이 문서를 물어볼 사람 |
| `purpose` | 권장 | 한 줄 | 검색 결과에서 뭔지 바로 보이게 |
| `review_by` | 선택 | `YYYY-MM-DD` | 이 날짜가 지나면 다시 확인해야 하는 문서 |
| `회의일` | 회의 문서 | `YYYY-MM-DD` | 실제 회의한 날 |
| `참석자` | 회의 문서 | 이름, 이름 | |
| `slack_url` | 자동 | URL | 수집 원본의 출처. 사람이 적지 않는다 |

---

## 2. `created` 와 `updated` 를 나눠 쓰는 이유

```
created: 2026-08-10     ← 이 문서가 처음 생긴 날
updated: 2026-08-12     ← 마지막으로 손댄 날
회의일:   2026-08-03     ← 논의가 실제로 있었던 날
```

셋이 다를 수 있다. **8월 3일 회의를 8월 10일에 문서로 만들고 8월 12일에 고쳤다면**
위와 같이 셋 다 다르게 적힌다. 이게 헷갈리면 "이 문서 최신인가?"를 판단할 수 없다.

**한 번 쓰고 안 고치는 문서에는 `updated` 가 없어도 된다.** 회의록이 대표적이다.
[[lint-규칙]] **L5** 는 git 이력을 보고 *실제로 두 번 이상 고쳐진* 문서만 지적한다.

> 처음에는 "모든 문서에 `updated` 필수"로 규칙을 잡았다가 54개 중 42개가 걸렸다.
> 규칙이 그 정도로 걸리면 아무도 안 본다. **문서가 아니라 규칙이 틀린 것이었다.**

---

## 3. `review_by` — 오래된 문서를 잡아내는 장치

시간이 지나면 틀려질 문서에만 붙인다.

```yaml
review_by: 2026-11-12    # 3개월 뒤 다시 확인
```

날짜가 지나면 [[lint-규칙]] **L7** 이 주간 리포트에 올린다. 자동으로 지우거나 고치지
않는다 — 여전히 맞는 내용일 수도 있으므로 사람이 판단한다.

**붙일 만한 문서**: 조직·담당자 정보, 외부 서비스 설정, 가격·계약 조건, "현재 상태" 를 적은 문서
**안 붙여도 되는 문서**: 회의록, 결정사항, 전사본 — 과거 사실이라 낡지 않는다

---

## 4. 자동 생성 문서

`index/` 와 `log/lint-report.md` 는 스크립트가 프론트매터까지 통째로 만든다.
**손으로 고치지 말 것** — 다음 실행에서 덮어써진다.

## 5. 흔한 실수

| 잘못 | 바르게 | 왜 |
|---|---|---|
| `created: 2026.08.12` | `created: 2026-08-12` | 하이픈이라야 날짜로 인식된다 |
| `created: 8/12` | `created: 2026-08-12` | 연도 없으면 정렬이 깨진다 |
| 프론트매터를 문서 중간에 | 반드시 **파일 맨 첫 줄**부터 | 첫 줄이 아니면 무시된다 |
| `---` 앞뒤에 빈 줄 | 빈 줄 없이 바로 | |
