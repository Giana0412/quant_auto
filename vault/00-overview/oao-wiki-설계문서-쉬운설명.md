# OAO Wiki — 쉬운 설명

> 이건 [[oao-wiki-설계문서]]의 **쉬운 말 버전**입니다.
> 같은 내용이고, 표현만 다릅니다. 자세한 근거와 숫자는 정본을 봐주세요.

---

## 한 줄로 말하면

**"회사의 기억을 한 곳에 모으는 일"** 입니다.

노트 앱을 바꾸자는 게 아닙니다.

---

## 1. 왜 하나요?

### 지금 뭐가 불편한가

회사 이야기가 **여기저기 흩어져 있습니다.** 슬랙에 조금, 노션에 조금,
구글 드라이브에 조금, 이메일에 조금, 깃허브에 조금.

그래서 이런 일이 생깁니다.

- **"그 건 어떻게 됐죠?"** → 매번 처음부터 다시 설명해야 함
- **"이거 왜 이렇게 정했더라?"** → 아무도 기억 못 함. 기록도 어디 있는지 모름
- AI한테 물어봐도 **회사 상황을 반쪽만 알고 있어서** 제대로 답을 못 함

실제로 회사 문서 폴더 몇 군데는 **3~4개월 동안 아무도 손대지 않았습니다.**
회의록 폴더는 **7주 동안 멈춰** 있었고요.

### 왜 멈췄나 — 게으름이 아닙니다

회의 끝나고 남은 거친 메모를 정식 문서로 만들어 올리는 절차가 **너무 번거로웠습니다.**
그래서 "나중에 해야지" 하다가 아무 데도 안 남은 겁니다.

### 그래서 뭘 하나

**메모를 남기는 문턱을 없앱니다.**
말로 "이거 정리해줘" 하면 AI가 알아서 정리하고 저장하고 팀에 공유합니다.

### 왜 하필 옵시디언인가요? 노션은요?

세 가지 차이가 있습니다.

| | 노션 / 컨플루언스 | 구글 드라이브 | **옵시디언** |
|---|---|---|---|
| **AI가 읽고 쓰기** | 사람이 복사해서 붙여넣어야 함 | 파일 보관함일 뿐 | **AI가 직접 읽고 씀** |
| **바뀐 내역** | 흐릿하게 남음 | 사실상 없음 | **누가 언제 뭘 바꿨는지 다 남음** |
| **나갈 때** | 데이터 묶여 있음 | 묶여 있음 | **그냥 텍스트 파일. 언제든 들고 나감** |

한 문장으로 하면 —
> **옵시디언이 좋은 이유는 노트 앱이라서가 아니라, AI와 같이 쓸 때 효과가 크기 때문입니다.**

### 걱정하실 만한 것

**"그럼 문서가 또 한 군데 늘어나는 거 아닌가요?"**

맞습니다. 그게 이 프로젝트가 실패하는 가장 흔한 방식이고, 시작 전부터 경고로 적어둔 내용입니다.
그래서 규칙을 하나 뒀습니다.

> **확정된 내용은 옵시디언에 두지 않고, 원래 있던 정식 문서 창고로 올려보냅니다.**

옵시디언은 **"확정되기 전의 이야기"** 를 담는 곳입니다.
정해지고 나면 원래 자리로 갑니다.

## 2. 누가 쓰나요?

**전원입니다.** 세일즈, 운영, 개발 다 같은 곳을 봅니다.

**그런데 옵시디언을 직접 만질 필요는 없습니다.**

```
   여러분: "이거 정리해서 넘겨줘"
              ↓
     Orca 에서 클로드가
     알아서 정리하고 저장하고 공유
              ↓
   옵시디언은 "읽고 찾아보는 창"
```

- 마크다운 문법? **몰라도 됩니다.**
- 파일 이름 규칙? **AI가 붙입니다.**
- 깃허브? **안 배우셔도 됩니다.**

여러분이 아셔야 할 말은 **두 개**입니다.

> **"이거 넘겨줘"** — 저장하고 팀에 공유해줘
> **"최신으로 받아줘"** — 남들이 쓴 거 가져와줘

## 3. 뭘 넣고 뭘 안 넣나요?

간단한 기준 두 개입니다.

> **"이거 바꾸면 코드도 같이 바꿔야 하나?"** → 예 = **기존 문서 창고에**
> **"3개월 뒤에 '왜 그렇게 했지?' 궁금할까?"** → 예 = **옵시디언에**

| | 옵시디언에 **넣습니다** | **안 넣습니다** |
|---|---|---|
| 회의 | 녹취·정리본·결정사항 | — |
| 세일즈 | 어디까지 진행됐나, 왜 막혔나, 공이 누구한테 있나 | 계약서 원본 → 드라이브 |
| 개발 | 왜 이렇게 정했는지, 아직 못 정한 것 | 기능 명세·개발 규칙 → 기존 창고 |
| 파일 | **글(텍스트)만** | PDF·이미지·PPT·녹음 → **드라이브** (링크만 걸어둠) |
| 개인 자료 | ❌ 절대 안 들어감 | 완전히 분리된 별도 저장소 |

## 4. 어떻게 생겼나요?

```
00 개요        이 프로젝트가 뭔지
01 구조        회사 코드가 어떻게 생겼는지
02 모듈        각 부분 설명
03 질문        아직 답 못 찾은 것들
04 기록        작업 일지
05 슬랙        슬랙에서 자동으로 모아온 원본
06 문서   ★   회의록이 쌓이는 곳
            ├ 전사본    → 있는 그대로 (보존용)
            ├ 정리본    → 읽기 좋게 (이해용)
            └ 결정사항  → 뭘 정했나 (실행용)
07 페르소나    AI 봇 설정
08 세일즈  ☆   파트너별 진행 상황 (만들 예정)
```

회의록이 **세 가지로 나뉘는 게 핵심**입니다.

| | 무엇 | 언제 보나 |
|---|---|---|
| **전사본** | 오간 말 그대로 | "그때 정확히 뭐라고 했지?" |
| **정리본** | 읽기 좋게 정리 | "이 회의 무슨 얘기였지?" |
| **결정사항** | 정한 것과 할 일만 | "나 뭐 해야 하지?" |

## 5. 누가 관리하나요?

| 무엇 | 누가 |
|---|---|
| 전체 구조·자동화 | 김규형 |
| 회의록 | **회의 소집한 사람** (녹취 파일만 올리면 끝) |
| 세일즈 현황 | 박지호 |
| 개발 관련 | 이준범 |

**회의 소집자는 파일만 올리면 됩니다.** 정리는 자동입니다.
정리까지 시키면 예전처럼 또 멈춥니다.

### 문서가 만들어지는 3가지 길

1. **말로** — Orca에 "이거 넘겨줘" (가장 많이 쓰실 방법)
2. **자동** — 슬랙에 파일 올리면 1시간 안에 알아서 회의록 3종이 만들어짐
3. **자동 백업** — 맥미니가 10분마다 알아서 백업

### 오래된 문서는?

- **결정한 내용은 지우지 않습니다.** 나중에 뒤집혀도 "예전엔 이렇게 정했다"가 자산이니까요.
  대신 새 문서에 "이건 예전 결정을 대체함"이라고 표시합니다.
- 진행 중이던 문서가 **3개월 넘게 안 바뀌면** 한 달에 한 번 모아서 정리합니다.

## 6. 어떻게 같이 보나요?

**깃허브**를 씁니다. 하지만 **깃허브를 배우실 필요는 없습니다.**

```
  "이거 넘겨줘"  →  클로드가 대신 올려줌  →  깃허브
                                              ↓
  "받아줘"      ←  클로드가 대신 가져옴   ←
```

**설치하실 것도 없습니다.** 옵시디언만 깔고 폴더 열면 끝입니다.
플러그인, 계정 연결, 토큰 발급 — **하나도 안 하셔도 됩니다.**

### 두 사람이 같은 문서를 동시에 고치면?

가끔 충돌이 납니다. 그러면 문서에 이상한 기호(`<<<<<<<`)가 보일 수 있어요.

**"충돌 났어, 풀어줘"** 라고만 하시면 됩니다.

이때 **여러분이 쓴 내용은 절대 지워지지 않습니다.** 이게 제일 중요합니다.
AI가 "둘 중 뭐가 맞겠지" 하고 임의로 지우지 못하게 막아뒀습니다.
둘 다 남긴 다음 이렇게 표시해서 사람이 고르게 합니다.

```
⚠️ 두 분이 같은 부분을 다르게 적었습니다. 맞는 쪽만 남겨주세요.
   - (규형) 기준은 공식 사이트까지
   - (준범) 기준은 공식 사이트 + 기사
```

| | |
|---|---|

옮기는 건 하루면 끝납니다. **승인만 해주시면 됩니다.**

## 8. 다른 도구랑은 어떻게 붙나요?

```
      사람(Orca+클로드)        AI 에이전트(맥미니)
              \                 /
               \               /
                옵시디언 (기억 창고)
                      |
        ┌────────┬────┴────┬────────┐
      깃허브    AWS      구글      슬랙
```

| | 상태 |
|---|---|
| **슬랙** | ✅ 파일 올리면 자동으로 회의록이 됨 + 할 일 기한을 슬랙으로 물어봄 |
| **구글 캘린더** | ✅ 회의에서 나온 할 일이 자동으로 캘린더에 들어감 |
| **깃허브** | ✅ 저장·공유 |
| **AWS** | ❌ 아직 |
| **AI 에이전트(헤르메스)** | ❌ 아직 — 옵시디언을 읽는 길이 아직 없음 |

### 역할 비유

> **옵시디언 = 기억**
> **AI 에이전트 = 생각하는 뇌**
> **Orca = 손발** (모으고 만들고)

지금은 기억이 여기저기 흩어져 있어서 뇌가 제 일을 못 합니다.
기억을 한 곳에 모으는 게 이 프로젝트입니다.

### 주의할 점 하나

옵시디언에 이것저것 많이 연결할수록, 어느 날 **"옵시디언이 회사의 진짜 원본"** 처럼
보이기 시작합니다. 그러면 처음에 걱정했던 문제(어디가 최신인지 헷갈림)가 그대로 돌아옵니다.

그래서 선을 하나 그어둡니다.
> **옵시디언은 여러 곳에서 읽어오기만 하고, 쓰는 건 글 파일로만.**

## 9. 플러그인은 어디까지 쓰나요?

**팀원분들은 아무것도 안 깔아도 됩니다.** (필요한 건 맥미니 한 대에만 있으면 됩니다)

| | |
|---|---|
| **필수** | 없음 |
| **자유** | 테마, 화면 배치, 단축키 — 마음대로 |
| **금지** | 특정 플러그인 없으면 글이 안 읽히는 것 |

마지막 항목이 중요합니다. 이 창고의 가치는 **"그냥 글 파일"** 이라는 데 있습니다.
특정 프로그램이 있어야만 읽히게 만드는 순간, AI가 읽는 기억 창고라는 목적이 무너집니다.

## 10. 잘 됐는지 어떻게 아나요?

### 이러면 실패입니다

1. 어디가 최신인지 헷갈리기 시작함
2. **글은 쌓이는데 정식 문서로 올라간 게 하나도 없음** ← 제일 위험
3. 결국 아무도 안 쓰고 슬랙·말로 돌아감

2번이 제일 흔한 실패입니다. 그냥 **메모 무덤**이 되는 거죠.

### 이렇게 확인합니다 (8/14 시작 → 2주 뒤 판정)

| 무엇 | 목표 |
|---|---|
| 회의 끝나고 하루 안에 결정사항이 남는 비율 | 10건 중 9건 |
| **정식 문서로 올라간 건수** | **0건이면 실패** |
| 세일즈·운영이 개발자 도움 없이 저장 성공 | 주 1회 이상, 3명 |
| 회의록 폴더가 또 멈추는가 | 2주 이상 공백 없기 |

### 한 문장으로 하면

> ### **"같은 설명을 두 번 하지 않게 되었는가."**
>
> 상욱님이 *"이거 하셨어요?"* 라고 묻지 않아도 상황을 아실 수 있는가.

### 그리고 별개로 하나 (급합니다)

문서 정리하다 발견한 건데, **회사 코드 저장소에 비밀번호가 그대로 적혀 있는 곳이 있습니다.**

- 여러 서비스 설정 파일에 **DB 비밀번호가 평문으로** (개발용·실서비스용 둘 다)
- 결제 관련 인증 파일이 저장소에 그대로 올라가 있음
- 그런데 회사 개발 규칙에는 **"비밀번호 하드코딩 금지"** 라고 적혀 있음 — 규칙과 실제가 어긋납니다

지금도 살아 있는 값인지 확인이 필요합니다. 이 프로젝트와는 별개지만 알려드립니다.
