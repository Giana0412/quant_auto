## 1. 목적

**Obsidian 앱 의존을 없앤다.**

현재 수집(`slack-sync`)과 GitHub 반영(`obsidian-git`)이 둘 다 Obsidian 플러그인이라
**앱이 떠 있어야만 동작한다.** launchd는 앱과 무관하게 돌기 때문에, 앱이 꺼지면
가운데 문서화 단계만 헛돌고 입력과 출력이 멈춘다.

실제로 2026-08-10 기준 이 상태였다 — 수집은 8/6, 자동 커밋은 8/9에 멈췄는데
launchd는 매시간 성실히 돌며 "처리할 새 원본 없음"만 18회 찍고 있었다.
**로그만 보면 정상으로 보인다는 게 이 고장의 가장 나쁜 점이다.**

### 얻는 것

| | 지금 | 개편 후 |
|---|---|---|
| 동작 조건 | Obsidian 앱 실행 중 | **launchd만** |
| 필수 플러그인 | 자동화 머신 2개 | **전사 통틀어 0개** |
| 도커 격리 | 불가 (GUI 앱) | **가능** — 260724 결정 `#3`과 정합 |
| 반영 지연 | 최대 10분 | 작업 직후 |
| 커밋 메시지 | 전부 `vault backup: <날짜>` | 내용 기반 |
| 커밋 빈도 | 10분마다 무조건 | 변경 있을 때만 |
| 기계 이식 | 플러그인 설치 + 토큰 재입력 | 스크립트 복사 + 경로 수정 |

### 대상

### 범위 밖 — 명시적으로 제외

**`personal/` 대상 스크립트 4개는 건드리지 않는다.**
`archive-newsletters.sh`, `daily-conclusion.sh`, `market-snapshot.sh`,
`weekly-newsletter-report.sh`.

이유: `personal/`은 **원격이 없는 로컬 전용 git 레포**다(2026-08-06 분리).
push할 대상 자체가 없고, vault 레포에서는 gitignore돼 있어 `obsidian-git`도
원래 손대지 않는다. 즉 **이 4개는 지금도 앞으로도 자동 커밋 대상이 아니다.**

> `vault/`에 쓰는 스크립트는 `process-slack-docs.sh` **하나뿐**이다(실측 확인).
> 따라서 B-2의 실제 적용 대상은 이 스크립트와 신규 `slack-collect.sh` 둘이다.

## 3. 구조 변화

### 현재

```
Slack ──▶ [slack-sync 플러그인] ──▶ 05-slack/ ──▶ [launchd: 문서화] ──▶ 06-docs/
              ⚠️ 앱 필요                              앱 무관
                                                                          │
                                          [obsidian-git 플러그인] ◀───────┘
                                              ⚠️ 앱 필요
                                                   │
                                                   ▼
                                                GitHub
```

### 개편 후

```
Slack ──▶ [launchd: slack-collect.sh] ──▶ 05-slack/
                                              │
                                              ▼
          [launchd: process-slack-docs.sh] ──▶ 06-docs/
                        │
                        ├─ 1단계 문서화
                        ├─ 2단계 액션아이템 → 캘린더
                        └─ 3단계 git pull → commit → push ──▶ GitHub

          전 구간 앱 무관. 플러그인 0개.
```

**수집을 별도 스크립트로 분리하는 이유**: 수집과 문서화는 실패 양상이 다르다
(전자는 네트워크·토큰, 후자는 Claude 실행). 한 스크립트에 묶으면 수집 실패가
문서화까지 막고, 로그에서 원인 분리도 어렵다.

launchd 잡은 **1개를 유지**하고 `process-slack-docs.sh` 맨 앞에서
`slack-collect.sh`를 호출한다. 잡을 2개로 늘리면 실행 순서가 보장되지 않는다.

## 5. B-1 — `slack-collect.sh` 신규

### 하는 일

`slack-sync` 플러그인(29KB)이 하던 일을 셸 + Slack API로 재구현한다.
필요한 API 호출 4개 중 **3개는 STAGE2가 이미 쓰고 있다.**

| 단계 | API | 기존 사용 |
|---|---|---|
| 1 | `conversations.list?types=public_channel,private_channel` | ✅ STAGE2 |
| 2 | `conversations.history?channel=<id>&oldest=<last_ts>` | ✅ STAGE2 |
| 3 | `users.list` (id → 이름) | ✅ STAGE2 |
| 4 | `files[].url_private` 다운로드 | 🆕 신규 |

호출 방식은 STAGE2와 동일하게 `curl -K .automation/.slack-auth.curlrc`를 쓴다.

### 실행 흐름

```
1. .slack.env 에서 토큰 → .slack-auth.curlrc 생성 (chmod 600)
2. 채널 목록을 순회한다 (§5-0)
3.   상태파일에서 channel_id·last_ts 읽기 (없으면 API로 채널ID 조회)
4.   conversations.history?oldest=<last_ts> 호출
5.   각 메시지에 대해:
       - bot_id 가 있으면 건너뜀            ← 되먹임 차단 (§5-4)
       - subtype 이 channel_join 등이면 건너뜀
       - files[] 가 있으면 첨부 처리 (§5-3)
       - 마크다운 변환 후 그 채널의 출력 폴더에 저장
6.   처리한 메시지 중 가장 큰 ts 를 그 채널의 last_ts 로 저장
7. .slack-auth.curlrc shred 삭제
8. 채널별 처리 건수 로그 출력
```

**6번을 5번 전체가 끝난 뒤에 채널마다 한 번만** 갱신한다. 메시지마다 갱신하면 중간에
실패했을 때 일부만 처리된 상태로 커서가 전진해 **구간 누락**이 난다.
채널 하나가 실패해도 **다른 채널의 커서는 건드리지 않는다.**

### 5-0. 채널 → 폴더 매핑 (다중 채널)

플러그인은 채널 목록(`channels: ["test_ob"]`)과 출력 폴더(`outputFolder`)를 각각
**하나씩**만 가진다. 채널마다 다른 폴더로 보낼 수 없다.

새 스크립트는 **채널 : 폴더를 1:1로 짝지어** 받는다.

```bash
# .automation/slack-collect.sh 상단
SLACK_CHANNELS=(
  "test_ob:vault/raw/slack"     # 회의 원본 → 06-docs 3종 문서로 정리됨
  "sales:vault/08-sales"       # 세일즈 메일 리뷰 → 그대로 보존
)
```

세일즈 채널이 필요한 이유와 전체 흐름은 [[전체-구조도]] §1-8 참조.
**채널 이름과 공개/비공개 여부는 확인 필요** — 비공개면 봇을 채널에 초대해야 읽힌다.

> `05-slack`은 1단계 문서화의 **입력**이지만, `08-sales`는 아니다.
> `process-slack-docs.sh`의 프롬프트는 `vault/raw/slack/*.md`만 훑으므로
> 세일즈 문서가 회의록 3종으로 잘못 가공되지 않는다 — 수정 불필요.

### 5-1. 상태 파일

```
.automation/slack-sync-state.json     (gitignore 아님 — 커밋해도 안전)
```

```json
{
  "channels": {
    "test_ob": {
      "channel_id": "C0BNG0J19FE",
      "last_ts": "1785983013.141989",
      "last_run": "2026-08-10T17:15:00+09:00",
      "last_result": "ok"
    },
    "sales": {
      "channel_id": null,
      "last_ts": null,
      "last_run": null,
      "last_result": null
    }
  }
}
```

> **`test_ob`의 초기값은 반드시 현재 플러그인 값을 그대로 이어받는다.**
> `lastSyncTimestamps.test_ob = 1785983013.141989` (2026-08-06 11:23:33)
> 비워두고 시작하면 채널 전체를 재수집해 **기존 문서와 중복**이 생긴다.
>
> **`sales`는 반대로 비워둔 채 시작해도 된다** — 이어받을 기존 수집물이 없다.
> 다만 채널 히스토리 전체를 한 번에 가져오므로, 어디부터 수집할지
> (예: 최근 3개월) 첫 실행 전에 정할 것. → §12 **Q5**

### 5-2. 파일명 규칙 — 현행 분석 후 재정의

현재 플러그인이 만든 이름은 규칙이 일정하지 않다.

| 실제 파일 | 추정 규칙 |
|---|---|
| `20260806_김규형_1024.md` | 날짜_사용자_시각 |
| `20260806_U0BC06201S5.md` | 날짜_사용자ID (이름 매핑 실패 시로 추정) |
| `20260806_clipboard_260804_AX.md` | 날짜_본문슬러그 |
| `20260806_10.md` | 날짜_본문슬러그 (짧게 잘림) |

**[제안] 결정적 규칙 하나로 통일한다.**

```
{YYYYMMDD}_{HHMM}_{사용자}.md          예: 20260810_1024_김규형.md
중복 시 뒤에 -2, -3                     예: 20260810_1024_김규형-2.md
이름 매핑 실패 시 사용자ID 사용
```

- 시각을 앞에 두어 **폴더가 시간순 정렬**된다
- 본문에서 슬러그를 뽑지 않으므로 **같은 메시지는 항상 같은 이름**이 나온다
  (재실행해도 중복 파일이 안 생긴다)

**기존 파일 5개는 그대로 둔다.** 1단계 문서화는 `05-slack/*.md`를 Glob으로 훑고
날짜는 내용에서 추론하므로 파일명 규칙이 섞여도 동작에 문제가 없다.

### 5-3. 첨부파일 처리

vault에는 md만 넣는다(260803 정리본 2-9).

| 확장자 | 처리 |
|---|---|
| `.txt`, `.md` | 다운로드 후 **본문에 코드블록으로 인라인** (현행과 동일) |
| 그 외 (pdf·이미지·zip 등) | **다운로드하지 않음.** 파일명 + Slack 링크만 기록 |

```markdown
📎 **2026.08.04 상욱님 현지님 규형님 원온원 (1).txt**
```(원문 내용)```

📎 **발표자료.pdf** — 바이너리이므로 vault에 저장하지 않음
   원본: https://OAO.slack.com/files/...
```

> `url_private` 다운로드에는 Authorization 헤더가 필요하다. `curl -K` 패턴을
> 그대로 쓰면 된다.

### 5-4. 봇 메시지 필터 — 되먹임 차단

**현재 STAGE2가 올린 기한 문의가 다시 원본으로 수집되고 있다.**

```
vault/raw/slack/20260806_clipboard_260804_AX.md
  ## 11:22 - Obsidian Vault Sync
  :clipboard: 260804-상욱현지규형원온원-결정사항 액션 아이템 기한을 정해주세요:
```

지금은 1단계가 "회의 내용 아님"으로 걸러 실질 피해는 없지만, 매시간 Claude에게
헛일을 시키고 05-slack을 오염시킨다.

→ **`bot_id` 필드가 있는 메시지는 수집하지 않는다.**
단, 사람이 봇에게 남긴 **답장은 사람 메시지이므로 수집 대상**이다
(STAGE2가 기한 답장을 읽는 경로와 충돌하지 않는다 — 그쪽은 별도로 API를 직접 본다).

## 6. B-2 — git 반영

### 공용 헬퍼로 분리

두 스크립트에 같은 코드를 복붙하지 않는다.

```
.automation/lib/git-sync.sh
```

```bash
#!/bin/bash
# vault 변경사항을 GitHub에 반영한다.
# 사용: vault_sync "커밋 메시지"
# 반환: 0 정상(변경 없음 포함) / 1 충돌 등으로 중단

vault_sync() {
  local msg="$1"
  cd "$VAULT_DIR" || return 1

  # 변경이 없으면 아무것도 하지 않는다
  if git diff --quiet && git diff --cached --quiet && \
     [ -z "$(git ls-files --others --exclude-standard vault/)" ]; then
    echo "변경 없음 — 반영 생략"
    return 0
  fi

  # B-3: 남의 변경을 먼저 받는다
  if ! git pull --no-rebase --quiet origin main; then
    echo "🔴 pull 충돌 — 자동 반영 중단. 사람이 확인해야 함"
    return 1
  fi

  git add vault/
  git commit --quiet -m "$msg"

  if ! git push --quiet origin main; then
    echo "⚠️ push 실패 — 커밋은 남아 있음. 다음 실행에서 재시도"
    return 1
  fi

  echo "반영 완료: $msg"
}
```

### 커밋 메시지 규칙

| 상황 | 메시지 |
|---|---|
| 수집 | `slack 수집: 3건 (2026-08-10)` |
| 문서화 | `회의록 생성: 260810-스폰서미팅 외 1건` |
| 액션아이템 | `액션아이템 갱신: 신규 4 / 기한확정 2` |

`vault backup: <날짜>`만 반복되던 것에 비해 **git log만 봐도 무슨 일이 있었는지 보인다.**

### 호출 위치

`process-slack-docs.sh` 안에서 단계마다 부른다.

```bash
. "$VAULT_DIR/.automation/lib/git-sync.sh"

"$VAULT_DIR/.automation/slack-collect.sh"   # 수집
vault_sync "slack 수집: ..."

"$CLAUDE_BIN" -p "$PROMPT" ...              # 1단계 문서화
vault_sync "회의록 생성: ..."

"$CLAUDE_BIN" -p "$PROMPT2" ...             # 2단계 액션아이템
vault_sync "액션아이템 갱신: ..."
```

단계마다 반영하면 **뒷 단계가 실패해도 앞 단계 결과는 이미 안전하다.**

### 프롬프트 수정

두 프롬프트에 박혀 있는 문구를 바꾼다.

```diff
- git commit/push는 하지 않는다 (obsidian-git이 별도로 자동 커밋한다).
+ git 명령을 실행하지 않는다 (스크립트가 별도로 처리한다).
```

에이전트에게 git 권한을 주지 않는 것은 그대로 유지한다
(1단계 `--allowedTools`에는 Bash 자체가 없다).

## 7. B-3 — 충돌 처리

`vault_sync`가 pull 실패 시 **중단하고 리턴**한다. 자동 병합을 시도하지 않는다.

**이유**: 사람이 안 보는 시각(새벽·주말)에 자동 병합이 잘못되면 아무도 모른 채
잘못된 내용이 GitHub에 올라간다. 지식 문서에서는 지연이 오염보다 낫다.

| 실패 | 동작 | 복구 |
|---|---|---|
| pull 충돌 | 중단, 로그에 🔴 | 사람이 `resolve-conflict` 스킬로 처리 |
| push 실패 (경합) | 중단, **커밋은 남김** | 다음 정시 실행이 자동 재시도 |
| Slack API 실패 | 수집 건너뜀, `last_ts` 미갱신 | 다음 실행이 같은 구간 재시도 |

> **[미결] 실패 알림.** 지금은 로그에만 남아 아무도 모른다.
> 알릴 곳은 **Slack `#test_ob`**로 한다 — 이미 인증이 돼 있고(`chat.postMessage`),
> 기한 문의가 나가는 채널과 같아서 새로 붙일 서비스가 없다. → §11

| 8 | 1시간 방치 후 자동 실행 정상 확인 | — |
