# 금융 헤드라인 감성 모델

파이프라인이 쓰는 **손으로 만든 78단어 사전**을 트랜스포머로 이길 수 있는지 재는 프로젝트.

개인 학습용이다. 대회 성적과는 무관하게 돌린다.

---

## 왜 이 문제인가

이 저장소에서 **가격을 예측하는 모델은 만들 수 없다.**

| 학습 데이터 후보 | 크기 |
|---|---|
| `book-log.jsonl` | 16줄 |
| `regime-log.jsonl` | 30줄 |

게다가 개별종목 스크리닝은 **생존편향 때문에 원리상 백테스트가 불가능**하다
(§`market_metrics.screen_universe`). 실제로 `VOL_PENALTY` 를 학습시키려다
"표본이 없어 학습할 수 없다"고 결론 내고 판단값으로 남긴 기록이 있다.

반면 **헤드라인은 다르다**:

- **라벨이 공짜** — 발행 후 N거래일 벤치 대비 초과수익이 정답이다
- **앞을 내다보지 않는다** — 헤드라인은 그 시점에 실재했고 라벨은 그 이후다
- **이길 대상이 명확하다** — `news_sentiment.py` 의 78단어 사전이 지금 운용 중이다

사전은 VADER 가 `beat` 를 폭행으로 읽어서 직접 만든 것이다. 이게 진짜 베이스라인이다.

---

## 구조

```
collect.py    헤드라인 수집 + 시장이 라벨을 단다 (append-only, 매일 돌림)
data.py       시간순 분할 · 3분위 라벨 · torch Dataset
baseline.py   기존 78단어 사전을 같은 테스트셋에 적용
model.py      DistilBERT + 직접 붙인 분류 헤드
train.py      손으로 쓴 학습 루프 (fit() 은 walkforward 가 재사용한다)
walkforward.py  날짜를 한 칸씩 밀며 재학습·평가 (rolling-origin)
```

`Trainer` 를 쓰지 않는다. PyTorch 를 배우는 게 목적이라 루프를 직접 썼다 —
DataLoader, 디바이스 이동, forward/backward, 워밍업 스케줄러, 그래디언트 클리핑,
클래스 가중, 조기 종료, 체크포인트가 전부 눈에 보이는 코드로 있다.

---

## 쓰는 법

```bash
python collect.py            # 수집 (매일 돌려 쌓는다)
python collect.py --stats    # 얼마나 쌓였나
python baseline.py           # 사전 성적 — 이걸 이겨야 한다
python train.py              # 학습 + 같은 테스트셋에서 비교
python walkforward.py        # 🔴 성적을 믿으려면 이쪽
```

### 왜 train.py 하나로는 부족한가

**독립 표본은 건수가 아니라 날짜 수다.** 같은 날 기사들은 같은 장을 공유하니
그날 지수가 오르면 그날 헤드라인은 대부분 '상승' 라벨을 받는다. 70/15/15 로
자르면 날짜가 27일이어도 **테스트 날짜는 5일**이고, 그 5일이 어떤 장이었냐에
따라 점수가 통째로 흔들린다.

실제로 10/23 첫 학습이 그랬다 — 검증 날짜 1일(6건)로 best 체크포인트를 골랐고
`history.json` 의 "검증정확도 83%" 는 **6개 중 5개**였다. train_loss 도
1.1208→1.0726 으로 무작위 추측값 ln(3)=1.0986 을 벗어나지 못했다.

`walkforward.py` 는 훈련창을 한 칸씩 늘려 가며 매번 다시 학습한다. 같은 27일에서
테스트 날짜가 5일이 아니라 **10~15일** 나오고, 구조 자체가 운용 상황과 같다
(늘 오늘까지로 배워 내일을 맞힌다). 비교 대상은 두 가지다:

| 기준선 | 뜻 |
|---|---|
| **다수클래스** | 그 폴드 *훈련셋*에서 가장 흔했던 클래스를 그대로 찍는다. 🔴 테스트셋의 다수 클래스가 아니다 — 그건 실시간에 알 수 없어서 기준선으로 쓰면 모델에 불리하게 과장된다 |
| **어휘사전** | 운영 중인 `score_text` (§bridge.py). 이걸 못 넘으면 딥러닝을 쓸 이유가 없다 |

```bash
python walkforward.py --step 2      # 폴드를 반으로 줄여 빠르게
python walkforward.py --no-lexicon  # 사전 비교 생략
```

폴드당 수십 초~수 분이 걸린다(폴드마다 처음부터 다시 학습한다 — 이어서 학습하면
앞 폴드의 테스트를 이미 본 상태가 된다).

## 🔴 이 프로젝트가 지키는 규칙

**1. 분할은 시간순이다.** 랜덤 분할하면 같은 날 같은 사건의 기사가 훈련셋과
테스트셋에 나뉘어 들어간다. 정확도가 치솟는데 그건 학습이 아니라 정답지를 본 것이다.

**2. 3분위 경계는 훈련셋에서만 구한다.** 전체 분위수를 쓰면 테스트셋 분포를
미리 본 것이다. 그래서 테스트셋 클래스 비율은 1/3씩이 아니고, 그게 정상이다.

**3. 매 에폭 테스트셋을 보지 않는다.** 보면 그게 또 하나의 검증셋이 된다.

**4. 사전을 못 이기면 못 이겼다고 적는다.** 그것도 결과다.

---

## 기대치

**방향 정확도 52~55% 나오면 잘 나온 것이다.** 발표된 금융 NLP 연구도 이 수준이다.
헤드라인 → 수익률은 신호 대 잡음비가 극도로 낮다.

이 프로젝트의 가치는 알파가 아니라 **평가 하네스**다. "얼마나 안 되는지를
정직하게 재는 법"을 만드는 것 — 이동원 교수가 말한 *"대회 전에 미리 정해둬야 할
판단 기준"* 이 정확히 이것이다.

## 알려진 한계

- **yfinance 는 최근 1주일 기사만 준다.** 소급 수집이 안 돼서 매일 쌓아야 한다
- **유니버스가 오늘 기준이다.** 헤드라인 자체엔 생존편향이 없지만, 모델이
  "망하는 회사의 뉴스"를 덜 보게 된다
- **발행일 종가 진입 가정.** 장중 뉴스면 이미 일부 반영된 가격이라
  실제보다 어려운 문제를 푼다 (낙관 쪽으로 새지 않게 일부러 이렇게 뒀다)

## 환경

M2 / 8GB 기준. DistilBERT(66M) + 배치 16 + `max_len` 64 가 스왑 없이 돈다.
MPS 는 fp16 autocast 가 들쭉날쭉해서 fp32 로 간다 — 속도보다 안정.
