# 링크 규칙

문서를 잇는 것이 이 vault 의 핵심이다. **아무도 링크하지 않는 문서는 검색으로만 닿고,
검색으로만 닿는 문서는 사실상 묻힌다.**

---

## 1. 기본형 — 짧은 이름

```md
[[전체-구조도]]                        ← 이렇게
[[../01-architecture/전체-구조도]]      ← 이렇게 하지 않는다
```

**이유: 폴더를 옮겨도 안 깨진다.** 2026-08-12 에 vault 를 5층으로 재배치하면서
문서 52개가 전부 이동했는데, 그 전에 링크 80개를 짧은 이름으로 통일해뒀기 때문에
**깨진 링크가 하나도 없었다.** 상대경로였다면 전부 깨졌다.

이게 성립하려면 **파일명이 vault 전체에서 유일해야 한다** ([[폴더-규칙]] §6).

---

## 2. 표시 이름 붙이기

문장 안에서 읽기 좋게 하려면 `|` 뒤에 보여줄 말을 적는다.

```md
[[260803-이벤트리서치옵시디언방향성논의-정리본|정리본]]
   ↑ 실제 파일명                              ↑ 화면에 보이는 말
```

### 표 안에서는 `\|` 로 이스케이프

`|` 는 표의 칸 구분자라서 그대로 쓰면 표가 깨진다.

```md
| 회의 | 문서 |
|---|---|
| 8/10 주간회의 | [[260810-주간회의-정리본\|정리본]] |
```

---

## 3. 새 문서를 만들면 반드시 어딘가에서 링크한다

만들고 끝내면 고아 문서가 된다. 최소 한 곳에서 걸어준다.

| 만든 문서 | 어디서 링크 |
|---|---|
| 구조·자동화 문서 | [[repo-map]] |
| 회의 3종 | 서로 (전사본 ↔ 정리본 ↔ 결정사항) + [[회의]] 목차가 자동 생성 |
| schema 문서 | [[repo-map]] + 다른 schema 문서에서 |

[[lint-규칙]] **L4** 가 고아 문서를 매주 잡아낸다. `raw/` 는 자동 수집 영역이라 제외한다.

---

## 4. 링크가 아닌 것을 링크처럼 쓰지 않기

문서 안에서 **예시**로 링크 표기를 보여줄 때는 백틱으로 감싼다. 안 그러면 실제 링크로
인식돼 "대상 없음" 오류가 난다.

```md
`[[문서이름]]` 형식으로 씁니다        ← 이렇게 (예시일 때)
[[문서이름]] 형식으로 씁니다          ← 이러면 깨진 링크로 잡힌다
```

## 5. 태그 — 최소한만 쓴다

먼저 솔직하게: **문서 54개 규모에서 태그의 실익은 거의 없다.** 폴더 5층과 링크로
이미 충분히 도달된다. 태그가 값을 하는 건 문서가 200개를 넘고 폴더 하나로 분류되지
않는 문서가 생길 때다.

### 지금 쓰는 것 — 상태 태그 3개뿐

```
#결정됨    확정. 이대로 실행한다
#미결      아직 정해지지 않음. 누가 정할지 함께 적을 것
#폐기      과거엔 맞았으나 지금은 아님 (지우지 말 것)
```

**`#폐기` 를 지우지 않는 이유**: "왜 안 하기로 했는지"가 남아 있어야 같은 논의를
반복하지 않는다.

### ⚠️ 번호 표기를 조심할 것

Obsidian 태그는 **숫자만으로는 만들어지지 않지만, 한글 조사가 붙으면 태그가 된다.**

```
결정 #12 를 참고        →  태그 아님  ✅
결정 #12가 맞다         →  #12가 라는 태그가 생김  ⚠️
```

그래서 본문에서는 **백틱으로 감싼다**.

```md
결정 `#12`가 맞다
```

실제로 이 문제로 `#9는` `#3과` `#10의` 같은 쓰레기 태그 14개가 만들어져 있었고,
의도해서 만든 태그(3개)보다 많았다. [[lint-규칙]] **L2** 가 이걸 잡는다.

### 나중에 (문서 200개 넘으면)

분야 태그를 프론트매터에 문서 단위로 붙인다: `#세일즈` `#파트너십` `#브랜드` `#제품` `#자동화`
**폴더와 겹치는 태그는 만들지 않는다** — 같은 걸 두 군데서 관리하게 된다.

### 하지 않을 것
계층 태그(`#a/b/c`), 사람 이름 태그, 날짜 태그 — 전부 프론트매터가 이미 한다.
