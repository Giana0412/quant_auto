# 준범님 원온원 (이벤트DB) #1 — 결정사항

## 결정사항
1. **개발은 김규형 로컬에서만** 한다. 맥미니에서 직접 코드 작업하지 않는다.
2. 반영 경로는 **로컬 개발 → GitHub PR → 머지 → 맥미니 자동 clone/pull → 도커 안 스킬 반영 → run 실행**.
3. **맥미니는 실행 전용**, 그것도 도커 컨테이너 안에서만 실행한다. (로컬 실행은 기기 전체 접근 권한 문제로 금지)
4. 역할 분담: **이준범이 실행 환경 세팅 담당**, 김규형은 **5개 스킬(discover/enrich/adjudicate/apply/source) 고도화**에 집중.
5. 중복 제거(유니크화)는 마지막 apply 단계가 아니라 **discover 단계**에서 수행한다 — 4개 사이트 목록 통합 후 유니크 대회 목록에만 enrich를 돌린다.
6. 같은 대회의 하프/풀은 별도 이벤트가 아니라 **discipline으로 분리**한다. 같은 대회의 여러 일정은 `start_at`/`end_at`으로 표현한다.
7. 김규형 로컬 개발 도구는 **Claude CLI + Orca IDE**로 세팅 (VS Code 대체 권장).
8. 파이프라인 실행 후에는 반드시 **DB에 직접 접속해 수집 정확도를 검수**한다.

## 액션 아이템

**김규형**
- 파이프라인 실행 구조(로컬/도커/크론/스킬 파일 위치, 수정 경로) 설명 자료 준비 — 제3자가 인수해 고칠 수 있는 수준으로
- 맥미니 로컬에서 작업한 내용 push → PR 생성 (당일 Claude 세션 리밋으로 이준범이 대행)
- 로컬에 Claude CLI 설치(상무님 계정 수령) + Orca IDE 설치 — 회의 중 진행
- discover 스킬에 유니크화 로직 반영
- 오수집 케이스 수정: 아쿠아슬론 챔피언십(2건→1건), 경주 국제 마라톤/경주 마라톤(동일 대회 중복), 인천 송도 국제 마라톤/국제 하프 마라톤(다른 대회인데 동일 날짜로 수집), 경청 마라톤/경주 마라톤(다른 대회를 파싱 오차로 오판)
- 크론을 dry-run이 아닌 라이브로 실행 (회의 시점 기준 수정했다고 언급)
- 5개 스킬 고도화

**이준범**
- 맥미니/도커 실행 환경 세팅 및 PR 머지 시 자동 반영 파이프라인 구성
- 김규형이 올린 PR 검토·머지
- (회의 중 완료) AWS 토큰 재발급

## 보류 / 미결정
- **enrich 단계 논의 전체** — 시작 직후 녹음 배터리 방전·시간 초과로 중단, 다음 회의로 이월
- 헤르메스 에이전트 컨테이너로의 이식 시점·범위 ("일단 차차 하고")
- adjudicate/apply의 동일 대회 판정 기준 개선 방안 구체안
- source scout/vet(신규 소스 확장)은 후순위 — "4개 사이트가 잘 돌아가면 20개로 늘리는 건 어렵지 않다"
