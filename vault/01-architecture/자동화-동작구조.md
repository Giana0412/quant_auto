> 이 문서의 모든 수치·설정값은 **2026-08-10 실측**이다. 추정이 섞인 곳은 그렇다고 표시했다.

## 0. 먼저 — 서버는 없다

가장 흔한 오해부터 짚는다. **우리가 운영하는 서버는 없다.**

옵시디언은 **로컬 앱**이다. 어딘가에 접속해서 문서를 여는 게 아니라, **각자 컴퓨터에
vault 폴더 전체 사본**이 있고 그걸 여는 것이다.

그럼 어떻게 같이 보나 — **GitHub이 유일한 만남의 장소**다. GitHub은 우리가 운영하지
않는다(깃허브가 운영한다). 우리는 각자 자기 사본을 GitHub에 올리고 내려받을 뿐이다.

```
                    ┌──────────────────────────────┐
                    │       GitHub (회사 레포)      │   ← 유일한 공유 지점
                    │   우리가 운영하는 서버 아님    │      (호스팅은 GitHub이)
                    └───────────┬──────────────────┘
                                │
       ┌────────────────────────┼────────────────────────┐
       │                        │                        │
┌──────┴────────┐      ┌────────┴───────┐      ┌─────────┴────────┐
│  팀원 맥 A     │      │  팀원 맥 B      │      │  ★ 자동화 머신    │
│               │      │                │      │   (맥미니 예정)   │
│ Obsidian 읽기  │      │ Obsidian 읽기   │      │                  │
│ Orca+Claude   │      │ Orca+Claude    │      │ 사람 없이 24시간  │
│  → push/pull  │      │  → push/pull   │      │ 알아서 도는 기계  │
│               │      │                │      │                  │
│ 플러그인 0개   │      │ 플러그인 0개    │      │ 플러그인 2개      │
└───────────────┘      └────────────────┘      └──────────────────┘
  vault 전체 사본        vault 전체 사본           vault 전체 사본(원본)
```

**"맥미니 한 대"가 특별한 이유는 서버라서가 아니라, 사람이 안 건드려도 24시간 켜져
있는 유일한 기계이기 때문이다.** 노트북은 덮으면 멈춘다.

## 1. 구성 요소 5개

전체 자동화는 부품 5개로 되어 있다. **이 중 2개는 Obsidian 앱 안에서만 돌고,
3개는 앱과 무관하게 돈다.** 이 구분이 이 문서에서 가장 중요하다.

| # | 부품 | 정체 | 앱 필요? | 역할 |
|---|---|---|---|---|
| 1 | `slack-sync` | Obsidian 플러그인 | **필요** | Slack → vault 원본 수집 |
| 2 | launchd + `process-slack-docs.sh` 1단계 | OS 예약 실행 + 스크립트 | 불필요 | 원본 → 회의록 3종 |
| 3 | 같은 스크립트 2단계 (STAGE2) | 스크립트 | 불필요 | 액션아이템 → 기한 문의 → 캘린더 |
| 4 | `obsidian-git` | Obsidian 플러그인 | **필요** | vault → GitHub 반영 |
| 5 | Orca + Claude Code | 사람이 여는 앱 | 불필요 | 사람의 쓰기·동기화 |

```
 [1] slack-sync ──▶ [2] 문서화 ──▶ [3] 액션아이템 ──▶ [4] obsidian-git ──▶ GitHub
   앱 안에서 돎      앱과 무관        앱과 무관         앱 안에서 돎
      ▲                                                     ▲
      └──────────── 앱이 꺼지면 이 둘이 멈춘다 ───────────────┘
                    (가운데 [2][3]만 계속 헛돈다)
```

**바로 이게 지금 벌어지고 있는 일이다.** §7 참조.

## 2. [1] Slack 수집 — `slack-sync` 플러그인

### 무엇을 하나

Slack API를 호출해 지정 채널의 메시지·첨부파일을 가져와 마크다운으로 바꿔
`vault/05-slack/`에 저장한다. **별도 서버를 띄우지 않는다** — 옵시디언 플러그인이
직접 Slack API를 부른다.

### 현재 설정 (`.obsidian/plugins/slack-sync/data.json`)

| 항목 | 값 |
|---|---|
| `channels` | `["test_ob"]` |
| `outputFolder` | `vault/05-slack` |
| `syncInterval` | `24` (시간) |
| `autoSync` | **`false`** 🔴 |
| `enableAISummary` | `false` |
| `lastSyncTimestamps.test_ob` | `1785983013.141989` → **2026-08-06 11:23:33** |

> **이 파일은 gitignore 대상이다.** Slack Bot Token이 평문으로 들어 있어서
> 절대 커밋하지 않는다. 따라서 이 설정은 기계마다 따로 잡아야 한다.

### 산출물 형식

```markdown
---
created: 2026-08-06
updated: 2026-08-06T02:26:29.565Z
slack_url: https://OAO.slack.com/archives/C0BNG0J19FE/p1785983013141989
---

## 11:23 - 김규형
(메시지 본문 / 📎 첨부파일 코드블록)
```

`slack_url`이 원본 역추적 경로가 되고, 뒤 단계에서 날짜 추론에도 쓰인다.

### 꺼지면

**입력이 끊긴다.** `05-slack`에 새 파일이 안 생기고, 뒤의 모든 단계가 할 일이 없어진다.

## 3. [2] 문서화 — launchd + 스크립트 1단계

### 스케줄 (`~/Library/LaunchAgents/com.giana.obsidian-slack-docs-sync.plist`)

```xml
StartInterval : 3600     (1시간마다)
RunAtLoad     : true     (부팅/등록 직후 1회)
ProgramArguments : /bin/bash .automation/process-slack-docs.sh
StandardOutPath  : .automation/logs/launchd.out.log
StandardErrorPath: .automation/logs/launchd.err.log
```

> `StartInterval`은 "마지막 실행으로부터 3600초"라서 시각이 조금씩 밀린다.
> 실제 로그상 오늘 실행 시각이 13:13 → 14:13 → 15:13 → 16:14 → 17:15로 밀리는 게 그 때문이다.
> 정해진 시각에 돌아야 하는 다른 잡들은 `StartCalendarInterval`을 쓴다(§6).
>
> 기계가 잠들어 있으면 그 시간의 실행은 건너뛰고 **깨어날 때 한 번** 돈다.

### 무엇을 하나

**헤드리스 Claude**를 부른다. 사람 없이 터미널에서 도는 Claude다.

```bash
/Users/gyuhyeongkim/.local/bin/claude -p "<프롬프트>" \
  --allowedTools "Read Write Edit Glob Grep"
```

프롬프트가 지시하는 작업 순서:

1. `vault/06-docs/_템플릿-가이드.md`를 **먼저 읽는다** (형식을 기억에 의존하지 않음)
2. `vault/05-slack/*.md` 전부 확인
3. 실질 내용이 있는지 판단 — "채널에 참여함" 같은 시스템 메시지는 건너뜀
4. 내용에서 **실제 회의 날짜**를 추론해 파일명(`YYMMDD-주제`) 결정
5. Glob으로 `01-전사본/`, `02-정리본/`, `03-결정사항/`에 이미 있는지 확인
   → **3종 다 있으면 건너뛴다 (중복 생성 금지)**
6. 없으면 템플릿대로 3종 작성
7. 처리 결과 요약 출력. 없으면 `"처리할 새 원본 없음"`만 출력

### 보안 설계 — 권한을 좁게 준다

`--allowedTools "Read Write Edit Glob Grep"` — **Bash도 네트워크도 없다.**
파일 읽고 쓰는 것만 가능하다. 사람이 안 보는 사이 도는 에이전트이므로
할 수 있는 일을 최소로 묶어둔 것이다.

### 로그

`.automation/logs/YYYYMMDD.log`에 실행 시각과 출력이 append된다.

```
=== 2026-08-10 17:15:10 [1/2 문서화] 실행 시작 ===
처리할 새 원본 없음
=== 2026-08-10 17:15:57 [1/2 문서화] 실행 종료 ===
```

## 4. [3] 액션아이템 → 캘린더 — 스크립트 2단계 (STAGE2)

`STAGE2_ENABLED=true` (현재 활성). 1단계 직후 이어서 돈다.

### 토큰을 다루는 방식 — 이 스크립트에서 가장 신경 쓴 부분

헤드리스 에이전트에게 Slack 토큰을 **절대 보여주지 않으면서** Slack API를 부르게 해야 한다.

```bash
# 1) 셸이 플러그인 설정에서 토큰을 꺼내
SLACK_TOKEN=$(python3 -c "...json.load(...)['slackToken']")

# 2) curl 설정 파일에 헤더로 박아두고 (권한 600)
printf 'header = "Authorization: Bearer %s"\n' "$SLACK_TOKEN" > .automation/.slack-auth.curlrc
chmod 600 .automation/.slack-auth.curlrc

# 3) 셸 변수는 즉시 폐기
unset SLACK_TOKEN

# 4) 에이전트는 "파일 경로"만 참조한다 — 토큰 값을 알 수 없다
#    curl -K .automation/.slack-auth.curlrc https://slack.com/api/...

# 5) 실행이 끝나면 파일을 지운다
shred -u .automation/.slack-auth.curlrc
```

> **왜 환경변수를 안 쓰나**: `Bash(curl:*)` 허용 패턴에서는 `$VAR` 같은 셸 확장이
> 정적 분석 불가로 차단된다. 그래서 `curl -K` 설정파일이 유일한 우회로다.
>
> 이 구조는 실제 사고 후에 도입됐다 — 초기엔 에이전트가 토큰을 curl 인자에 직접
> 타이핑해 **세션 트랜스크립트에 평문으로 남는** 일이 있었다.

### 캘린더 계정 분리 — 하드코딩

```bash
STAGE2_CALENDAR_ID="gkimam@oao-corp.com"   # 회사 캘린더 고정
```

프롬프트에도 *"calendarId를 명시적으로 넣고, 기본/primary 같은 암묵적 대상에
의존하지 않는다"*고 못박았고, `--allowedTools`에도 **회사 계정 도구만** 넣었다.

```
mcp__claude_ai_Google_Calendar__{create_event,update_event,list_events,list_calendars}
```

개인 캘린더 도구(`mcp__google-calendar-personal__*`)는 **의도적으로 제외**했다.
회사 액션아이템이 개인 캘린더로 잘못 들어간 사고가 실제로 있었고, 그 재발 방지책이다.

### 상태 저장소 — `.automation/action-items.json`

```json
[{
  "id": "...",
  "source_doc": "vault/06-docs/03-결정사항/260803-....md",
  "owner": "김규형",
  "task": "TC 문서 생성",
  "status": "awaiting_due_date | scheduled | reminded",
  "due_date": "2026-08-12",
  "due_time": "14:00",          // 시각 언급 없었으면 null
  "slack_prompt_ts": "1785983013.141989",
  "calendar_event_id": "..."
}]
```

이 파일이 **어디까지 처리했는지 기억하는 유일한 수단**이다. 지워지면 이미 물어본
항목을 다시 물어본다.

### 3단계 처리 — A / B / C

**[A] 신규 액션아이템 발견**

`03-결정사항/*.md`를 훑어 `source_doc` 기준으로 아직 없는 문서의 `## 액션 아이템`을
파싱 → `status=awaiting_due_date`로 등록 → Slack `chat.postMessage`로 기한을 묻는다.

```
📋 <문서명> 액션 아이템 기한을 정해주세요:
1) [김규형] TC 문서 생성
2) [이준범] draft → publish 전환

각 번호에 날짜로 답장해주세요 (예: 1) 8/10  2) 8/8).
스레드 답장이든 채널에 그냥 타이핑이든 상관없습니다.
```

응답의 `ts`를 `slack_prompt_ts`에 저장한다.

**[B] 답장 확인 — 두 경로를 모두 본다**

| API | 무엇을 잡나 |
|---|---|
| `conversations.replies?ts=<slack_prompt_ts>` | 스레드로 답장한 경우 |
| `conversations.history?oldest=<slack_prompt_ts>` | **채널에 그냥 타이핑한 경우** |

> 두 번째가 있는 이유: 처음엔 `replies`만 봤는데, 실제 사람은 스레드가 아니라
> 채널에 그냥 답을 타이핑했다. 라이브 테스트에서 못 잡는 걸 발견해 추가한 것이다.

자연어 날짜·시각을 파싱한다 (`"8/10 오후 2시"` → `2026-08-10` + `14:00`, KST 기준).
그 뒤 `users.list`로 담당자 이름 → Slack user id를 찾고, 캘린더 일정을 만든다.

- `due_time` 있음 → 그 시각 시작 **1시간 일정** (Asia/Seoul)
- `due_time` 없음 → **종일 일정**

> 종일 일정만 만들다가 시각 정보를 버리는 버그가 있어 `due_time`을 나중에 추가했다.

**[C] 당일 알림**

`due_date == 오늘(KST)`인 항목에 멘션을 건다.

```
<@U01234>님, 오늘 이거 해야 함: TC 문서 생성
```

→ `status=reminded`로 변경.

## 5. [4] GitHub 반영 — `obsidian-git` 플러그인

### 왜 필요한가

**스크립트가 만든 문서는 파일로만 존재한다.** 누군가 GitHub에 올려야 한다.
그런데 `.automation/*.sh` **6개 전부 직접 커밋하지 않는다.** 프롬프트에 명시돼 있다.

> `git commit/push는 하지 않는다 (obsidian-git이 별도로 자동 커밋한다)`

그래서 그 역할을 `obsidian-git`이 맡는다.

### 현재 설정

```json
"autoSaveInterval"  : 10,        // 10분마다 커밋
"autoPushInterval"  : 10,        // 10분마다 push   ← 2026-08-10 수정 (0이었음)
"autoPullInterval"  : 10,        // 10분마다 pull   ← 2026-08-10 수정 (0이었음)
"autoPullOnBoot"    : true,
"pullBeforePush"    : true,
"syncMethod"        : "merge",
"autoCommitMessage" : "vault backup: {{date}}"
```

커밋 메시지가 전부 `vault backup: 2026-08-09 10:47:59` 형태인 게 이 플러그인이 만든
흔적이다.

### 구조적 약점

**이건 Obsidian 앱 안에서 도는 플러그인이다.** 앱이 꺼져 있으면 커밋도 push도 없다.
launchd는 앱과 무관하게 계속 도니까, **문서는 계속 만들어지는데 아무도 올리지 않는
상태**가 될 수 있다. §7이 정확히 그 상태다.

## 6. 전체 스케줄 (실측)

| 시각 | 잡 | 방식 | 대상 |
|---|---|---|---|
| **매시간** | `obsidian-slack-docs-sync` | `StartInterval 3600` | vault (회의록 + 액션아이템) |
| 매일 20:00 | `newsletter-archive` | `StartCalendarInterval` | personal (뉴스레터) |
| 매일 20:15 | `market-snapshot` | `StartCalendarInterval` | personal (시장 데이터) |
| 매일 20:30 | `daily-conclusion` | `StartCalendarInterval` | personal (일일 결론) |
| 매주 월 09:00 | `newsletter-weekly-report` | `StartCalendarInterval` | personal (주간 리포트) |

> 아래 4개는 **개인 영역(`personal/`, 로컬 전용 repo)** 이고 회사 vault와 무관하다.
> 같은 기계에서 돌 뿐이며, 맥미니 이전 대상인지는 별도 판단이 필요하다.

### 회의 하나가 흘러가는 전체 타임라인

```
14:00  회의 종료
14:05  ClovaNote 전사본을 Slack #test_ob 에 업로드           ← 사람이 하는 유일한 일
        │
        ▼  (slack-sync)
~14:05  vault/05-slack/20260810_xxx.md 생성
        │
        ▼  (launchd, 다음 정시)
15:13   헤드리스 Claude 1단계
        → 06-docs/01-전사본, 02-정리본, 03-결정사항 3종 생성
        │
        ▼  (같은 실행, 2단계)
15:14   결정사항에서 액션아이템 파싱
        → Slack에 "기한을 정해주세요" 게시
        │
        ▼  (obsidian-git, 10분 내)
~15:20  커밋 + GitHub push
        │
        ▼
        팀원들이 Orca에 "받아줘" 하거나, 옵시디언을 열면 확인 가능

(이후)  사람이 Slack에 "1) 8/12 오후 2시" 답장
        → 다음 정시 실행에서 파싱 → 회사 캘린더에 일정 생성
        → 당일 아침 실행에서 Slack 멘션 알림
```

## 9. 권고 — 플러그인 의존을 0으로

### 문제의 뿌리

입력(slack-sync)과 출력(obsidian-git)이 **GUI 앱 안에서만 도는 플러그인**이라는 것.
그래서 앱이 꺼지면 멈추고, 도커에도 넣을 수 없고, 기계마다 설정을 따로 잡아야 한다.

### 해결

| 부품 | 지금 | 바꾸면 |
|---|---|---|
| 수집 | slack-sync 플러그인 | 스크립트가 Slack API 직접 호출 (STAGE2가 이미 `curl -K`로 하고 있다) |
| 반영 | obsidian-git 플러그인 | 스크립트 끝에 `git add/commit/push` 3줄 |

### 얻는 것

```
앱 상시 실행 요건   : 필요 → 불필요
필수 플러그인       : 자동화 머신 2개 → 전사 통틀어 0개
도커 격리           : 불가 → 가능 (결정 #3과 정합)
기계별 설정         : 토큰 재입력 필요 → 스크립트 하나로 이식
실패 지점           : "앱이 꺼져 있었다" → 없음
```

### [결정됨] 이전 때 함께 적용한다 — 2026-08-10

노트북에서 임시 복구하지 않고 맥미니 이전 시 한 번에 처리하기로 정했다.
어차피 경로 수정과 재설정이 필요하고, 플러그인을 없애면 §8의 5·6번 작업
(플러그인 설치·토큰 재입력)이 통째로 사라져 이전 자체가 더 간단해진다.

→ 실행 항목은 **§11 체크리스트**
