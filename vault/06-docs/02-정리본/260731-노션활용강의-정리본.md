# 노션(Notion) 활용 강의 — 정리본

- 일시: 2026-07-31 (금) 오전 9:21
- 참석자: 김규형, 이호림(강사)
- 강의명: 노션 활용 방안 강의 + 고객 DB 관리/세일즈 개인 질문
- 총 러닝타임: 약 51분 (1부 42분 + 2부 10분)

## 1. 한줄 요약

- 노션의 DB·뷰·관계형·버튼 자동화·AI 기능을 활용해 프로젝트/업무 관리와 고객 DB(영업 CRM)를 어떻게 구성하는지 배운 강의였다.

## 2. 한눈에 보기

| 구분 | 핵심 내용 |
|---|---|
| 업무/프로젝트 관리 | 프로젝트 DB + 태스크 DB 2개를 관계형으로 연결, 템플릿·버튼으로 자동 생성 |
| 고객 DB / 영업(CRM) | 고객별 페이지 + 영업 단계 보드, 계약완료 시 후속 업무 자동 생성 |
| 데이터베이스 기본 | 표·캘린더·보드·갤러리·타임라인 5종이 실무 핵심 |
| AI 기능 | AI 노트(회의 자동 기록/요약), 에이전트(반복 업무 자동화) |
| 비용 관리 | 게스트 계정 + 대표(또는 공용) 계정 1개만 유료 결제 |
| 권한 관리 | 페이지 단위로 팀원별 접근/편집/읽기 권한 설정 가능 |

## 3. 핵심 논의

### 3-1. 프로젝트/업무 관리 구조

- **핵심 원리**: 데이터베이스는 최소한으로(예: 프로젝트 DB + 세부 태스크 DB 2개) 만들고, **보기 방식(뷰)** 을 여러 개 세팅해 활용
  - 리더용 뷰 = 전체 프로젝트 현황
  - 실무자용 뷰 = 진행 중인 세부 태스크 보드
  - 팀별 뷰 = 파트별 필터링된 페이지
- **관계형(Relation)**: 프로젝트–태스크, 기업–고객처럼 서로 다른 DB의 항목을 연결하는 기능. 처음엔 개념이 어렵지만 익숙해지면 매우 유용
- **링크된 데이터베이스**: 원본 DB 하나를 여러 페이지에 배치(연동)하는 기능. 어디서 수정해도 실시간으로 모든 곳에 반영됨 → 전사 페이지/팀 페이지를 따로 만들어도 데이터 이중 관리 불필요
- **템플릿 + 버튼 자동화**: 템플릿을 누르면 필요한 하위 페이지·태스크가 자동 생성되도록 조건을 미리 세팅 가능 (신규 프로젝트 착수 시 반복되는 공통 업무에 유용)
- **대시보드**: 최근 출시된 기능으로 매출 등 지표를 표/그래프로 시각화 가능. 단, **전년 대비 비교 그래프는 아직 미지원**

### 3-2. 고객 DB / 영업(CRM) 관리

- **구조**: B2B든 B2C든 세팅 구조는 동일 — 고객 1명당 페이지 1개, 상담 히스토리·구매 내역·관심 제품·계약 히스토리를 한 페이지에 모아 관리
- **영업 단계 관리**: 보드(칸반) 뷰로 영업 단계별 진행 상황을 시각화
- **자동화 예시**: 상태값을 '계약 완료'로 바꾸는 순간, 계약 후 필요한 서류 목록·후속 업무가 자동 생성되도록 설정 가능 → 매번 수동으로 페이지를 만드는 시간 낭비 방지
- **회의록 → DB 자동 반영**: 완전 자동은 아니지만, AI(에이전트) 기능에 "회의록 기반으로 영업 관련 액션을 정리해서 채워줘"라고 요청하면 **초안** 형태로 반영 가능. 처음엔 정확도가 낮아 여러 번 테스트·개선 필요
- **구글 시트 대체**: 날짜별 구글 시트 수기 임포트 방식 대신, 프로젝트 DB + 태스크 DB 구조와 버튼 자동화를 참고해 전환 가능

### 3-3. 데이터베이스 기본 개념

- 노션의 모든 요소는 **블록** 단위 (텍스트, 이미지, 표 등). `/`(슬래시)로 모든 블록 호출 가능
- 데이터베이스 종류는 10여 가지지만, 실무에서 자주 쓰는 건 아래 5가지

| 보기 방식 | 용도 |
|---|---|
| 표 | 가장 기본, 속성값 관리에 적합 (기업 사용 권장) |
| 캘린더 | 날짜 기반 일정 관리 |
| 보드 | 진행 단계별(칸반) 관리, 그룹 기준을 담당자/카테고리 등으로 자유 변경 |
| 갤러리 | 카드형(이미지 포함), 포트폴리오·프로젝트 소개용 |
| 타임라인 | 기간(시작~종료) 기반 간트 차트 |

- ※ 리스트 뷰는 정보량이 적어 기업 실무에는 비추천
- 처음 DB 설계 시 필요한 속성값(담당자/날짜/상태/메모 등)부터 고민 후 점진적으로 발전시키는 것을 추천. 조직이 성장하면 구조도 계속 개편 필요

### 3-4. 노션 AI 기능

- **AI 노트**: 회의 녹음 → 자동 받아쓰기 + 요약 + 액션 아이템 추출. 담당자 태그 시 에이전트 기능으로 해당 담당자 태스크 DB에 자동 반영 가능
  - 화자 인식(개인 매핑)은 완벽하지 않음 → 맥락 기반으로 "참석자 A/B" 수준까지만 구분
  - 녹음 중 '메모' 칸에 놓치면 안 되는 내용을 직접 입력하면 요약에 반영됨
- **에이전트 기능**: 반복 입력(예: 매월 고정비), 주간 리포트/브리핑 등을 데이터베이스 기준으로 자동 생성
- **비용 절감 팁**: 게스트 계정은 AI 기능 사용 불가 → 초기 조직은 대표 계정 1개만 유료 결제하고 나머지는 게스트로 초대. AI 기능이 꼭 필요하면 회사 공용 계정을 별도로 유료 생성해 다수가 동시 로그인해 활용

### 3-5. 버튼 자동화 심화

- **DB 내부 버튼**: 특정 한 행(row)에 대한 상태 변경 등 개별 작업 처리
- **DB 외부 버튼**: 페이지 생성, 다른 화면 이동 등 더 넓은 범위의 작업 처리
- 여러 데이터베이스를 한 번에 처리하는 버튼도 구성 가능하나, 각 DB별로 작업(action)을 개별 추가해야 함

### 3-6. 권한 설정

- 우측 상단 '공유'에서 초대된 팀원 목록 확인 및 페이지별 접근 권한 개별 조정 가능
- 특정 팀원을 특정 페이지에서 제외 → 해당 팀원에게는 그 페이지가 보이지 않음
- 페이지 단위로 '읽기 전용' 등 세부 권한 부여 가능 (예: HR 연차 관리 페이지 등 민감 정보 보호)

## 4. 맥락 / 배경 — 자유 토론에서 나온 인사이트

- 노션을 잘 활용하려면 **업무 도메인에 대한 개념 정리·구조화 역량**이 선행되어야 함
- 카카오톡 등 메신저는 휘발성이 있는 반면, 노션은 시간이 걸리더라도 데이터가 축적됨
- 향후 노션과 클로드(Claude) 등 AI를 연결해 활용하려는 니즈가 있음
- B2B 영업(웨딩홀 등)에서는 관계·이력 관리가 핵심이며, B2C는 1:1 대응에 구조적 한계가 있음

## 5. 미결정 사항 / 추가 논의 필요

- 강의 성격의 자리로, 우리 조직에 실제 어떤 구조를 적용할지는 미정 — 아래 액션 아이템은 모두 "검토/제안" 단계
- 노션 자체의 제약으로 남는 항목: 대시보드의 전년 대비 비교 그래프 미지원, AI 노트의 화자 인식(개인 매핑) 불완전
- 회의록 → 영업 DB 자동 반영은 초안 수준까지만 가능하며 정확도 확보에 반복 테스트 필요
