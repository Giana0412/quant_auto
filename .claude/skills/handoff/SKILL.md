# Handoff (다 썼으니 넘겨줘)

## 목표

사용자가 커밋·PR·푸시 개념을 전혀 모르는 상태에서 **"이거 넘겨줘" 한 마디로**
내용이 템플릿에 맞게 정리되어 vault에 저장되고 팀 전체에 동기화되게 한다.

근거: `vault/06-docs/03-결정사항/260803-이벤트리서치옵시디언방향성논의-결정사항.md` #10, #12

## 언제 사용하는가?

- "다 썼어, 넘겨줘" / "이거 정리해서 올려줘" / "저장해줘"
- 회의 전사본 텍스트를 붙여넣고 문서로 만들어 달라고 할 때
- 세일즈 진행 상황을 말로 불러주고 기록해 달라고 할 때

## 절대 규칙

1. **사용자에게 git 용어를 쓰지 않는다.** "커밋", "푸시", "브랜치", "PR" 같은 단어를
   결과 보고에 넣지 않는다. "저장했습니다", "팀에 공유됐습니다"로 말한다.
2. **`vault/` 밖을 건드리지 않는다.** `personal/`, `company-src/`, `.automation/`,
   `.omc/`는 이 스킬의 작업 대상이 아니다.
3. **바이너리를 vault에 넣지 않는다.** `.pdf` `.docx` `.pptx` `.xlsx` `.png` `.mp3` 등을
   받으면 저장하지 말고, 텍스트만 추출해서 문서로 만들고 **원본은 Google Drive에 두시라고 안내**한다.
   (결정: vault에는 md만 — 260803 정리본 2-9)
4. **시크릿을 저장하지 않는다.** 토큰·비밀번호·API 키·DB 접속정보가 본문에 보이면
   저장 전에 중단하고 사용자에게 알린다.
5. **기존 문서를 덮어쓰지 않는다.** 같은 이름이 이미 있으면 사용자에게 확인한다.

## AI 수행 절차

### Step 1: 입력 확보

다음 중 어느 형태인지 파악한다.

| 입력 형태 | 처리 |
|---|---|
| 대화창에 붙여넣은 텍스트 | 그대로 사용 |
| 파일 경로를 준 경우 | Read로 읽음. 비텍스트면 텍스트 추출 후 원본은 Drive 안내 |
| "슬랙에 올린 거" | `vault/05-slack/` 에서 최근 파일 확인 |
| 아무 것도 없음 | 무엇을 넘길지 물어본다 |

### Step 2: 종류 판별

내용을 보고 아래 중 하나로 분류한다. **애매하면 AskUserQuestion으로 확인**한다.

| 종류 | 저장 위치 | 판별 힌트 |
|---|---|---|
| 회의 (전사본/정리본/결정사항 3종) | `vault/06-docs/` | 화자·시각 표기, 여러 사람 발언, "회의", "원온원" |
| 세일즈 진행 상황 | `vault/08-sales/pipelines/{파트너}.md` | 파트너사명, 견적, 미팅, 계약 |
| 개발 결정·미해결 질문 | `vault/03-notes/questions.md` 에 추가 | "확인 필요", "왜 이렇게 됐는지 모름" |
| 그 외 일반 노트 | 사용자에게 위치 확인 | — |

### Step 3: 템플릿 적용

**회의인 경우 — `vault/06-docs/_템플릿-가이드.md` 를 먼저 읽고 그 형식을 그대로 따른다.**
요약해서 기억하지 말고 매번 읽는다. 3종을 모두 만든다.

- `01-전사본/YYMMDD-주제-전사본.md` — 원문 보존. **요약 금지**, "원본과 동일" 같은 축약 금지
- `02-정리본/YYMMDD-주제-정리본.md` — 한줄요약 / 핵심논의 / 맥락배경 / 미결정 / 액션아이템(표)
- `03-결정사항/YYMMDD-주제-결정사항.md` — 결정 / 보류 / 액션아이템. 공식 결정이 없으면 "없음"으로 명시

날짜는 **내용에서 추론한 실제 회의일**을 쓴다 (파일 생성일이 아니다).

세일즈인 경우 frontmatter 고정 필드:

```yaml
---
partner: 채널A
ball: our | their          # 지금 공이 누구에게 있는지
last_contact: 2026-08-10
next_action: 견적서 발송
block_reason: 예산 확정 대기   # 막혀 있으면
event_d_day: D-73             # 연결된 이벤트가 있으면
---
```

### Step 4: 중복 확인 후 저장

1. Glob으로 같은 `YYMMDD-주제-*` 가 이미 있는지 확인
2. 3종이 다 있으면 **건너뛴다** (중복 생성 금지). 하나라도 없으면 없는 것만 만든다
3. 이미 있는 문서를 고쳐야 하면 사용자에게 먼저 확인
4. 저장 후 관련 문서 상호링크를 붙인다 (`[[../01-전사본/...|전사본]]` 형식)

### Step 5: 동기화

사용자는 "넘겨줘"라고 했으므로 **10분 자동 동기화를 기다리지 않고 즉시 반영**한다.

```bash
git pull --no-rebase origin main    # 먼저 남의 변경을 받는다
git add vault/
git commit -m "<사람이 읽을 수 있는 한 줄 요약>"
git push origin main
```

- **충돌이 나면 여기서 멈추고 `resolve-conflict` 스킬로 넘어간다.** 직접 `--force`,
  `reset --hard`, `checkout --theirs` 를 쓰지 않는다.
- push 실패 시 재시도 1회. 그래도 실패하면 사용자에게 "지금 팀 공유는 실패했지만
  내용은 안전하게 저장됐다"고 정확히 알린다 (저장과 공유를 구분해서 보고).

### Step 6: 보고

git 용어 없이, 이 형식으로 짧게.

```
정리해서 저장했습니다.

  회의록 3종 — 260810-스폰서미팅
    · 전사본   (원문 보존)
    · 정리본   (핵심 논의 5건)
    · 결정사항 (결정 3건 / 보류 1건 / 액션 4건)

팀에 공유 완료됐습니다. 다른 분들은 옵시디언을 켜면 10분 안에 보입니다.

확인이 필요한 것:
  · 액션아이템 2건에 담당자가 비어 있습니다
  · "클투"는 클리포드로 추정해서 적었습니다
```

액션아이템에 기한이 있으면, `.automation/process-slack-docs.sh` STAGE2가
다음 실행(매시)에 Slack 기한 문의와 캘린더 등록을 자동으로 처리한다는 점을 덧붙인다.

## 실패 시 대응

| 상황 | 대응 |
|---|---|
| 충돌 발생 | `resolve-conflict` 스킬로 인계 |
| 인증 실패 | "GitHub 접근 권한 문제입니다. 김규형님께 문의하세요"로 안내 |
| 바이너리 입력 | 텍스트만 추출해 저장 + 원본은 Drive 안내 |
| 시크릿 발견 | 저장 중단 + 사용자에게 알림 |
| 내용이 너무 짧아 분류 불가 | 억지로 만들지 말고 되묻는다 |

## 관련

- 템플릿: `vault/06-docs/_템플릿-가이드.md`
- 충돌 처리: `resolve-conflict` 스킬
- 확정 문서를 모노레포로 올릴 때: `promote` 스킬
