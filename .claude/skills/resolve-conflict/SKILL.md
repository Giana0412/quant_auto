# Resolve Conflict (충돌 풀어줘)

## 목표

비개발자가 `<<<<<<< HEAD` 같은 걸 마주쳤을 때 **"충돌 났어, 풀어줘" 한 마디로**
아무것도 잃지 않고 복구되게 한다.

## 언제 사용하는가?

- 노트에 `<<<<<<<`, `=======`, `>>>>>>>` 가 보인다고 할 때
- Obsidian이 동기화 에러 알림을 띄웠을 때
- `handoff` 스킬이 충돌로 중단하고 넘겨줬을 때
- "며칠 전에 쓴 게 안 보인다"고 할 때 (미푸시 누적일 수 있음)

## 절대 규칙 — 이것만은 지킨다

1. **사용자 작업을 절대 버리지 않는다.**
   `git reset --hard`, `git checkout --ours/--theirs`, `git push --force`,
   `git clean -fd`, `git stash drop` 을 **쓰지 않는다.**
   충돌한 지식 문서는 **양쪽 다 남기는 것이 언제나 안전한 기본값**이다.
   한쪽을 버리는 판단이 필요하면 반드시 사용자에게 묻는다.
2. **손대기 전에 백업한다.** 작업 시작 전 `git branch backup/conflict-<날짜시각>` 로
   현재 상태를 박제한다. 복구 실패 시 여기로 되돌린다.
3. **git 용어로 보고하지 않는다.** "합쳤습니다", "둘 다 남겼습니다"로 말한다.

## AI 수행 절차

### Step 0: 백업

```bash
git branch "backup/conflict-$(date +%Y%m%d-%H%M%S)"
```

### Step 1: 진단 — 진짜 충돌인지부터 확인

증상이 "동기화가 안 된다"여도 원인은 여러 가지다. 순서대로 확인한다.

```bash
git status --short --branch
git rev-list --left-right --count origin/main...main   # 뒤처짐/앞섬
grep -rl '^<<<<<<< ' vault/ 2>/dev/null                # 실제 충돌 마커
```

| 진단 결과 | 원인 | 처리 |
|---|---|---|
| 충돌 마커 있음 | 진짜 충돌 | Step 2로 |
| 마커 없고 로컬만 앞섬 | 푸시가 안 되고 있음 | Step 4 (그냥 push) |
| 마커 없고 원격만 앞섬 | pull을 안 받음 | `git pull --no-rebase` 후 Step 4 |
| `UU`/`AA`/`DU` 상태 파일 있음 | 머지 진행 중 | Step 2로 |
| 인증 오류 | 권한 문제 | 복구 시도하지 말고 김규형님께 문의 안내 |

### Step 2: 충돌 유형별 처리

각 충돌 파일을 Read해서 유형을 판별한다.

#### (a) 같은 문서를 두 사람이 각각 고침 — `both modified`

**기본 동작: 양쪽 내용을 모두 보존해서 병합한다.**

- 서로 다른 절(section)을 고친 경우 → 두 변경을 그대로 합친다
- **같은 줄**을 다르게 고친 경우 → 두 버전을 나란히 남기고 사람이 고르게 한다:

```md
<!-- ⚠️ 두 분이 같은 부분을 다르게 적었습니다. 맞는 쪽만 남기고 이 주석을 지워주세요. -->
- (A안 / 김규형) 완성도 기준은 공식 사이트까지
- (B안 / 이준범) 완성도 기준은 공식 사이트 + 기사
```

절대 임의로 한쪽을 고르지 않는다. 지식 문서는 **틀린 내용이 남는 것보다 두 개가 남는 것이 낫다.**

#### (b) 같은 이름으로 각자 새 문서를 만듦 — `both added`

내용이 다른 문서라면 **둘 다 남긴다.** 뒤에 온 쪽 파일명에 구분자를 붙인다
(`260810-스폰서미팅-정리본.md` → `260810-스폰서미팅-정리본-2.md`)
후 사용자에게 병합할지 묻는다. 내용이 사실상 같으면 하나만 남긴다.

#### (c) 한쪽이 지우고 한쪽이 고침 — `deleted by us/them`

**자동 판단 금지.** 삭제는 되돌리기 어려우므로 반드시 사용자에게 묻는다.
기본 제안은 "일단 살려둔다".

#### (d) 설정 파일 충돌 — `.obsidian/*.json`

지식 자산이 아니므로 원격(`--theirs`)을 채택해도 안전한 유일한 예외다.
단, `.obsidian/plugins/obsidian-git/data.json`(팀 공통 동기화 설정)이면
사용자에게 알린 뒤 처리한다.

`.omc/`, `.automation/logs/`, `.obsidian/workspace.json`, `company-src/` 가
충돌 목록에 보이면 **이미 gitignore된 항목이므로 추적에서 빼면 된다** —
과거에 커밋된 잔재다.

### Step 3: 마커 완전 제거 검증

```bash
grep -rn '^<<<<<<< \|^=======$\|^>>>>>>> ' vault/ && echo "🔴 마커 남음" || echo "✅ 깨끗함"
```

마커가 하나라도 남아 있으면 **커밋하지 않는다.** 남은 파일을 다시 처리한다.

### Step 4: 마무리 동기화

```bash
git add -A
git commit -m "충돌 해소: <무엇과 무엇을 합쳤는지>"
git pull --no-rebase origin main
git push origin main
```

성공하면 Step 0의 백업 브랜치를 지운다:
```bash
git branch -D "backup/conflict-..."
```
**실패했거나 사용자 확인이 남아 있으면 백업을 지우지 않는다.**

### Step 5: 보고

```
동기화 복구했습니다.

  충돌 2건 — 둘 다 내용은 그대로 살렸습니다
    · 260810-스폰서미팅-정리본.md
        규형님이 고친 "액션아이템"과 준범님이 고친 "미결정" 둘 다 반영됨
    · 260810-스폰서미팅-결정사항.md
        같은 줄을 다르게 적으셔서 두 버전을 나란히 남겼습니다
        → 파일 안의 ⚠️ 표시를 찾아 맞는 쪽만 남겨주세요

지금은 팀과 동일한 상태입니다.
```

한쪽이라도 사람 확인이 필요하면 **"복구했습니다"로 끝내지 말고** 무엇을 확인해야
하는지 파일명과 위치까지 명시한다.

## 재발 방지 점검

복구 후, 원인이 아래에 해당하면 짚어준다.

| 원인 | 안내 |
|---|---|
| 자동 동기화가 꺼져 있었음 | `.obsidian/plugins/obsidian-git/data.json` 의 `autoPushInterval`/`autoPullInterval` 이 0이 아닌지 확인 |
| 오래 앱을 꺼둔 뒤 편집 | 다음부터는 옵시디언을 켜고 잠깐 기다렸다가(자동 pull) 편집하시라고 안내 |
| 같은 문서를 동시에 편집 | 세일즈 파이프라인처럼 파트너당 파일을 쪼개는 쪽을 제안 |

## 관련

- 저장·동기화: `handoff` 스킬
- 백업 브랜치는 `git branch --list 'backup/*'` 로 확인할 수 있다
