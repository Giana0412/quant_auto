# 회의록/문서 3종 템플릿 가이드

OAO 회의록 Drive 표준을 이 vault의 Slack → 문서화 파이프라인에 맞게 적용한 것.
Slack(`test_ob` 채널)에 업로드된 파일을 [[../05-slack/index|vault/05-slack]]이 원본 그대로 수집하면,
Claude가 이 템플릿에 맞춰 `vault/06-docs/`에 3종 문서를 생성한다.

## 0) 프론트매터 — 3종 모두 공통 (필수)

```yaml
---
created: YYYY-MM-DD        # 필수. 문서를 만든 날 (회의한 날이 아니다)
updated: YYYY-MM-DD        # 필수. 고칠 때마다 갱신
회의일: YYYY-MM-DD          # 회의 문서만
참석자: 이름1, 이름2
---
```

> **`updated`를 빼먹지 말 것.** 2026-08-12 lint 첫 실행에서 문서 50개 중 42개가
> 걸렸는데, 원인은 사람이 아니라 **이 가이드에 프론트매터 규격이 없었던 것**이었다.
> 생성기가 규격을 모르면 산출물 전체가 같은 위반을 갖는다.
>
> 규칙 전체와 검사 도구: `.automation/wiki_lint.py` (`python3 .automation/wiki_lint.py`)

## 폴더 구조

```
06-docs/
├── 01-전사본/    YYMMDD-주제-전사본.md   (원문 보존, 요약 없음)
├── 02-정리본/    YYMMDD-주제-정리본.md   (사람이 읽는 구조화 요약)
└── 03-결정사항/  YYMMDD-주제-결정사항.md (실행/추적용 압축본)
```

예: `260806-광고소개서피드백-전사본.md`, `...-정리본.md`, `...-결정사항.md`

역할: **전사본 = 보존**, **정리본 = 이해**, **결정사항 = 실행**.

---

## 1) 전사본 템플릿

원칙: 요약 없이 원문 최대한 그대로. "원본과 동일" 같은 축약 금지. 오탈자 교정 최소화.

```md
# <회의명>

- 회의일: YYYY-MM-DD
- 참석자: 이름1, 이름2, 이름3
- 원본: (Slack 업로드 파일명 / ClovaNote 전사본 등)
- 주의: 자동 전사 특성상 화자명, 숫자, 고유명사 오기가 있을 수 있음

---

## 전사 원문

[00:00:00] 화자A: ...
[00:00:12] 화자B: ...
[00:00:35] 화자A: ...
...
```

## 2) 정리본 템플릿

원칙: 단순 bullet dump 금지. 핵심 논의 / 배경 / 미결정 / 액션을 분리. 나중에 다시 봤을 때 맥락이 살아있어야 함.

```md
# <회의명> — 정리본

- 일시: YYYY-MM-DD HH:MM
- 참석자: 이름1, 이름2, 이름3

---

## 1. 한줄 요약

- 이번 회의는 <무엇을 결정/정렬/검토했는지>에 대한 논의였다.

## 2. 핵심 논의

### 2-1. 주제 A
- ...

### 2-2. 주제 B
- ...

## 3. 맥락 / 배경

- 왜 이 논의가 나왔는지
- 이전 결정이나 상황과 어떤 연결이 있는지

## 4. 미결정 사항 / 추가 논의 필요

- ...

## 5. 액션 아이템

| 항목 | 담당 | 기한 | 비고 |
|---|---|---|---|
| ... | ... | ... | ... |

---
※ 전사 기반 정리본이며, 화자/수치 일부는 원문 재확인이 필요할 수 있음.
```

## 3) 결정사항 템플릿

원칙: 제일 짧고 명확하게 — 실행과 추적용.

```md
# <회의명> — 결정사항

## 1. 결정사항
1. ...
2. ...

## 2. 미결정 / 보류
- ...

## 3. 액션 아이템

**담당자A**
- ...

**담당자B**
- ...

## 4. 참고
- 전사 불확실 항목: ...
- 관련 문서 / 링크: ...
```

(더 간단한 대안 포맷: `## 결정사항` bullet + `## 액션 아이템`(`- [담당자] ...`) + `## 보류사항` bullet만 쓰는 축약형도 허용)
