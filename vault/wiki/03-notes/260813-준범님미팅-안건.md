## 🔴 0. 먼저 — 기한이 내일이다

[[260810-주간회의-결정사항]] 결정 2번:

> 옵시디언 + 헤르메스 + 크론 연동은 추가 리서치 없이 바로 붙여보며 베스트 케이스를
> 찾는 방식으로 진행 — 목표는 화요일 퇴근 전 완료, 늦어도 **목요일에는 "동작한다"고
> 말할 수 있는 상태**

**오늘이 수요일(8/12), 기한은 내일(8/13)이다.** 현재 상태:

| 구성요소 | 상태 |
|---|---|
| 크론 | ✅ launchd 6개 잡, 오늘 전부 종료코드 0 |
| 옵시디언 | ✅ vault 5층 구조, lint 0건, 목차 자동 생성 |
| **헤르메스 연동** | ❌ **미구현 — vault 를 읽는 경로가 아직 없다** |

**"동작한다"의 정의를 맞춰야 한다.** 지금 상태를 동작으로 볼 것인지, 헤르메스가
vault 를 읽는 것까지여야 하는지에 따라 내일 답이 달라진다.

## 🔴 1. 아키텍처 간극 — 같은 지적이 반복될 위험

[[260724-준범님원온원이벤트DB-정리본]] §2-3 에서 이준범이 지적한 것:

> 사전 합의는 "이벤트 리서치는 3파이프라인, **헤르메스 에이전트의 별도 컨테이너
> 안에서** Claude 모델을 붙여 돌린다" 였는데 실제로는 그렇게 되어 있지 않다

**지금 옵시디언 자동화가 정확히 같은 형태다.**

```
합의된 그림 (260803 결정 13번)
  옵시디언 = 메모리 / 헤르메스 = CPU / 오르카 = 팔다리

실제 구현 (2026-08-12)
  옵시디언 = 메모리      ✅
  launchd + Claude CLI  ← 김규형 노트북에서 직접. 헤르메스 컨테이너 밖
  오르카 = 팔다리        ✅
```

`ingest`·`lint`·`index`·`query` 를 전부 만들었지만, **헤르메스가 아니라 노트북의
Claude CLI 가 실행한다.** 260724 때와 같은 간극이고, 지적받기 전에 먼저 꺼내는 게 낫다.

### 물어볼 것

1. vault 자동화도 **헤르메스 컨테이너 안으로** 들어가야 하는가?
2. 아니라면 헤르메스와 이 자동화의 경계는 무엇인가?
   (지금 만든 사서 역할 → [[에이전트-역할]])
3. 260710 미결 *"어느 에이전트(심바/라피키/제3의 에이전트)에 붙일지 미정"* 은
   여전히 미정인가?

## 2. 헤르메스가 vault 를 읽는 경로 [제안]

결정 13번의 **"헤르메스 = CPU"** 가 성립하려면 헤르메스가 메모리를 읽어야 한다.
지금은 못 읽는다 ([[oao-wiki-설계문서]] §8).

방법 후보 셋. **셋 다 vault 를 읽기 전용으로만 연다.**

| | 방법 | 장점 | 단점 |
|---|---|---|---|
| A | 헤르메스 컨테이너가 **repo 를 clone** 해서 파일로 읽기 | 단순. 260724 결정 2·3번(도커 안에서 clone)과 같은 패턴 | 주기적 pull 필요 |
| B | vault 를 **MCP 서버로 노출** | 모델 중립. 검색·인용까지 제공 가능 | 서버를 하나 띄워야 함 — "서버 없음" 원칙과 충돌 |
| C | 헤르메스가 **`ask` 스킬을 호출** | 이미 만든 규약을 그대로 씀 | Claude Code 의존 — 260811 핵심논의 2 와 충돌 |

**A 를 권한다.** 이벤트리서치가 이미 쓰는 패턴이고 서버가 늘지 않는다.
[[query-규칙]] 의 검색 순서와 출처 표기 규약은 A 에서도 그대로 적용된다.

## 5. 더 제안할 수 있는 것

### 5-1. 성공 지표를 측정 가능하게

[[oao-wiki-설계문서]] §10 의 **조회율**이 핵심 지표인데 **측정 수단이 없다.**
"기억이 실제로 조회되는가"를 못 재면 무덤인지 창고인지 알 수 없다.

→ `ask` 스킬 호출을 `vault/log/` 에 남기면 잰다. 무엇을 물었고 답을 찾았는지까지.
**답을 못 찾은 질문 목록이 곧 다음에 채울 곳이다.**

### 5-2. raw 인입 경로 일반화

260811 핵심논의 6 은 *"누군가 회의 전사본을 raw 에 넣고"* 인데, 지금 ingest 입력은
`raw/slack` 고정이다. 사람이 파일을 놓는 경로가 없다.

→ `raw/` 전체를 훑도록 넓히면 된다. **Slack 을 안 써도 구조가 안 무너진다.**

### 5-3. 팀원 온보딩 문서

규칙 문서 5종은 생겼지만 *"처음 온 사람이 무엇부터 하는가"* 가 없다.
전사 도입을 하려면 이게 있어야 한다.
