# 에이전트 역할 — Hermes 는 사서다

260811 싱크의 도서관 비유에서 나온 정의다.

| | |
|---|---|
| **위키** | 회사의 정리된 책과 공용 지식 |
| **raw** | 회의 전사본·슬랙 로그 같은 원본 자료 |
| **schema** | 도서관의 분류 체계와 운영 규칙 |
| **Hermes** | raw 를 정리하고 낡은 책을 정리하며 연결성을 강화하는 **사서** |

사서는 책을 쓰지 않는다. **들어온 자료를 제자리에 꽂고, 목록을 갱신하고,
낡은 것을 골라내고, 찾는 사람에게 꺼내 준다.**

---

## 1. 무엇을 언제 하는가

| 일 | 주기 | 상태 | 실행 주체 |
|---|---|---|---|
| **수집** raw 에 원본 넣기 | 1시간 | ✅ 자동 | `slack-collect.sh` |
| **ingest** raw → wiki 3종 문서 | 1시간 | ✅ 자동 | `process-slack-docs.sh` 2단계 |
| **index** 목차 재생성 | ingest 직후 | ✅ 자동 | `wiki_index.py` |
| **액션아이템** 결정사항 → 기한 문의 → 캘린더 | 1시간 | ⏸️ 꺼둠 | 같은 스크립트 3단계 |
| **lint** 규칙 위반 점검 | 월 09:30 | ✅ 자동 | `wiki-lint.sh` |
| **query** 질문에 근거로 답하기 | 요청 시 | ✅ 스킬 | `.claude/skills/ask` |
| **링크 강화** 끊긴 맥락 잇기 | — | 🟠 **반자동** | lint L4 가 고아 문서만 잡음 |
| **낡은 문서 정리** | — | 🟠 **반자동** | lint L7 이 `review_by` 경과만 잡음 |
| **중복 제거·위치 재배치** | — | ❌ **미구현** | 사람이 판단 |

**🟠·❌ 를 숨기지 않는다.** 260811 싱크에서 이준범이 사서의 일로 꼽은 것 중
"중복 제거, 위치 재배치"는 아직 자동화돼 있지 않다. lint 가 *징후*를 보고할 뿐
합칠지 옮길지는 사람이 정한다.

## 2. 하루 흐름

```
매시간 정각 무렵
  ├─ 네트워크 확인 (안 되면 조용히 건너뛰고 다음 시간에 재시도)
  ├─ [1/3] Slack #test_ob 수집 → raw/slack/
  ├─ [2/3] raw 훑어 새 원본이 있으면 wiki 3종 생성 → index 재생성
  └─ [3/3] 결정사항의 액션아이템 처리        ⏸️ 지금은 꺼둠

매주 월 09:30
  └─ lint 7종 검사 → log/lint-report.md

사람이 부를 때
  ├─ "왜 이렇게 했지?"   → ask 스킬 (읽기 전용)
  ├─ "이거 정리해줘"     → handoff 스킬 (쓰기)
  ├─ "충돌 풀어줘"       → resolve-conflict 스킬
  └─ "코드로 만들어야 해" → promote 스킬
```

## 3. 권한 — 층마다 다르다

```
raw/      읽기만.   ← 절대 고치지 않는다 (lint L6 이 감시)
wiki/     읽기·쓰기
schema/   읽기만.   ← 규칙은 사람이 정한다
index/    쓰기.     ← 통째로 덮어쓴다 (사람이 손댈 파일이 아니다)
log/      덧붙이기
personal/ 접근 금지 ← Read 권한 자체를 vault/ 로 스코프한다
```

**`schema/` 를 에이전트가 못 고치게 하는 이유**: 규칙을 지키는 쪽이 규칙을 바꿀 수
있으면 규칙이 아니다. lint 가 걸릴 때 규칙을 완화하는 방향으로 스스로 고치면
검사 자체가 무의미해진다.

**자동화가 실제로 쓰는 권한도 좁혀 놨다.**
`--allowedTools "Read Write Edit Glob Grep"` — 문서화 단계에는 Bash 도 네트워크도 없다.

## 4. 사람과 사서의 경계

| 사서(Hermes)가 하는 것 | 사람이 하는 것 |
|---|---|
| 원본을 제자리에 꽂기 | **무엇을 원본으로 넣을지 정하기** |
| 템플릿대로 3종 문서 만들기 | 내용이 맞는지 확인 |
| 규칙 위반 찾아 보고 | **고칠지 말지 판단** |
| 근거를 찾아 답하기 | 답을 믿을지 판단 |
| 목차 갱신 | 규칙(`schema/`) 정하기 |

**lint 가 자동 수정을 하지 않는 이유가 여기 있다.** 사람이 의도해서 만든 예외를
사서가 지워버리면, 서가는 깔끔해지지만 도서관은 나빠진다.

## 5. 조용한 실패를 막는 장치

이 vault 에서 실제로 두 번 크게 데였다.

| 사고 | 기간 | 왜 몰랐나 |
|---|---|---|
| Slack 수집 정지 | 6일 | 플러그인이 앱 종료 시 멈추는데 로그엔 "처리할 새 원본 없음"만 |
| STAGE2 사망 | 6일 | stdout 만 봤고 stderr 에 같은 오류 95건이 쌓여 있었다 |
| 개인 자동화 정지 | 4일 | `set -e` 로 첫 실패에 죽고 재시도·알림 없음 |

그래서 넣은 장치들이다.

| 장치 | 무엇을 막나 |
|---|---|
| 네트워크 대기 + 재시도 3회 | 깨어난 직후의 일시적 실패 |
| 모든 메시지를 **stdout** 으로 | stderr 로 새서 아무도 안 보는 일 |
| lint 리포트를 **vault 안**에 | 로그 파일은 아무도 안 본다 |
| index 의 "빠진 문서" 표시 | 3종 중 일부만 생성된 회의 |
| 앱 의존 제거 (수집·ingest) | 사람이 앱을 닫으면 멈추는 구조 |

> **원칙**: 실패는 조용하면 안 된다. 자동화가 멈춘 걸 6일 뒤에 아는 건
> 자동화가 없는 것보다 나쁘다 — 돌고 있다고 믿기 때문이다.

| 실패 알림 | 로그에만 남는다. Slack `#test_ob` 게시가 후보 (개편안 Q1) |
