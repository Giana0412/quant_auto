## 0. 한 장 요약

**무엇을 만드는가** — 회사의 흩어진 맥락을 한 곳에 모으는 **에이전트용 메모리 레이어**.
문서 도구를 갈아타는 일이 아니다.

**핵심 프레임** (260803 결정 #13)
> **옵시디언 = 메모리 / 헤르메스 에이전트 = CPU / 오르카 = 팔다리**

**어떻게 쓰나** — 사람은 옵시디언을 손으로 편집하지 않는다.
전원이 **Orca + Claude Code**에 말로 시키고, Claude가 템플릿에 맞춰 md를 쓰고 GitHub에 올린다.
옵시디언은 **읽고 찾는 창**이다.

**지키는 선** — git이 SSOT라는 OAO 원칙을 깨지 않는다.
경계는 *확정 전/후*가 아니라 **문서의 성격**이다.
코드와 함께 움직여야 하는 문서는 git에, **회사의 맥락과 의사결정은 옵시디언에 영구히** 남는다.
확정됐다고 옵시디언에서 내보내지 않는다 — 그러면 기억 창고가 아니게 된다.

**지금 상태** — 개인 테스트 단계 완료. 전사 도입 블로커 5개 중 **3개 해소(8/10)**,
2개가 남았고 둘 다 기술 문제가 아니라 **결정·커뮤니케이션 사안**이다 (§12).

**일정** (260728 결정 #6) — 이번 주(8/10~8/14)가 "옵시디언 전사 도입 시도" 주간.

## 1. 목적 — Why Obsidian?

### 풀려는 문제

`vault-rationale.md`(2026-07-29 기획서)가 진단한 것은 "문서가 부족하다"가 아니라
**"맥락이 흩어져 있어 사람도 에이전트도 매번 재구성해야 한다"** 이다.

모노레포에서 실제로 죽어 있던 영역:

| 영역 | 정지 기간 (2026-07 기준) |
|---|---|
| `docs/brand`, `docs/partnerships` | 3~4개월 커밋 0건 |
| `docs/meetings` | 7주 (43건이 잘 관리되다 5월 말 멈춤) |

원인은 게으름이 아니라 **마찰**이다. 회의 직후의 거친 메모를 git에 커밋하기엔 절차가
무겁고, 실행 코드와 실험 내러티브가 섞이면 가독성도 떨어진다. 그래서 아무 데도 안 남는다.

결과: 세일즈 맥락(공이 누구에게 있는지, 마지막 미팅 무브, 막힌 이유)이 이메일·구두·
Slack·Notion에 흩어져 **매번 재구성해서 설명**해야 하고, 에이전트는 팀 상황을 부분적으로만 이해한다.

### 왜 Notion / Confluence / Drive가 아닌가

| | Notion / Confluence | Google Drive | **Obsidian** |
|---|---|---|---|
| 에이전트 접근 | API 또는 복붙 — *"클로드에게 시키고 복붙해서 올려야"* | 바이너리 보관소, 맥락 아님 | **로컬 md. Claude가 직접 read/write** |
| 버전·이력 | 페이지 히스토리 (diff 빈약) | 사실상 없음 | **git diff / blame / PR이 그냥 따라옴** |
| 맥락 조립 | DB 관계형 | 폴더 | **`[[링크]]` 그래프** |
| 락인 | 있음 | 있음 | **없음 (플레인 텍스트)** |

260803 회의에서 이준범이 정리한 문장이 핵심이다.

> *"옵시디언이 각광받는 이유는 노트 앱이라서가 아니라 **클로드와 함께 썼을 때의 효과** 때문."*

### 오해를 막기 위해 — Obsidian은 git의 대체가 아니다

기획서가 **배드 시나리오 1번**으로 명시한 것이 *"Obsidian을 공식 source of truth로 만드는 것"*이다.
그렇게 되면 Symba가 `/oao/docs`와 vault 둘 다 봐야 하고, 어느 쪽이 최신인지 헷갈리며,
"git이 SSOT"라는 원칙이 깨진다.

**이 설계는 대체가 아니라 영역 분리다.**

```
코드에 종속된 문서 (기능 명세·API 설계·개발 규칙·QA)  →  git 모노레포 docs/
회사의 맥락과 의사결정 (회의·결정·세일즈·파트너십)      →  Obsidian vault   ★영구
대용량 원본 · 바이너리                                  →  Google Drive (링크만)
```

**두 영역은 겹치지 않는다.** 겹치지 않으므로 "어느 쪽이 최신인지" 문제가 애초에 생기지 않는다.
배드 시나리오 1번은 *같은 문서가 양쪽에 있을 때* 터지는 것이지,
서로 다른 종류의 문서가 각자의 자리에 있을 때 터지는 게 아니다.

기능 명세는 코드가 바뀌면 같이 바뀌어야 하므로 코드 옆에 있어야 하고,
"우리가 왜 그렇게 정했는지"는 코드와 무관하게 계속 살아 있어야 하므로 vault에 있어야 한다.

## 2. 대상 & 공유 — Who & Where

### 누가 읽고 쓰나

**[결정됨]** 팀별로 입력 통로를 나누는 안(세일즈=Notion / 개발=git)은 **폐기**.
전원이 같은 vault 하나를 본다. — 260803 결정 #9

**단, "다이렉트로 쓴다"가 옵시디언 앱에서 손으로 편집한다는 뜻은 아니다.**
결정 #9는 *팀마다 다른 툴을 거치는 구조를 없앤다*는 뜻이고,
그 입력 통로를 결정 #12가 **"오르카 + 클로드 직접 방식"**으로 명시했다.
즉 **사람의 쓰기 경로는 전원 Orca + Claude Code 하나**이며, 옵시디언은 읽는 창이다.

| 역할 | 사람 | 하는 일 | 쓰는 방법 |
|---|---|---|---|
| **세일즈** | 박지호, 이상욱 | 파트너별 딜 맥락, 미팅 무브, 막힌 이유 | Orca에 말 → Claude가 기록 |
| **운영** | — | 회의 원문 전달, 결정사항 확인 | Slack 업로드(자동) 또는 Orca |
| **개발** | 이준범, 김규형 | 모듈 문서, 결정 이력, 미해결 질문 | Orca에 말 → Claude가 기록 |
| **에이전트** | 헤르메스, Symba | 수집·연산 (별도 레이어 — §8) | 자동 |

**아무도 md 문법을 배우지 않는다.** 템플릿 준수·파일명 규칙·링크 연결은 전부 Claude가 한다.

### 어디서 공유되나

| 층 | 수단 |
|---|---|
| **정본 저장** | **회사 GitHub 레포 (신설 예정)** — private |
| **원본·자동화 머신** | **맥미니 (이전 예정)** — 260803 결정 #11. **현재는 김규형 노트북**(`Mac14,2` MacBook Air)에서 운영 중이며, 노트북이 닫혀 있는 동안은 자동화가 멈춘다 |
| **쓰기 인터페이스** | **Orca + Claude Code** (사람) / Slack 업로드 (자동 수집) |
| **읽기 인터페이스** | Obsidian 앱 + Slack 알림 |
| **에이전트 접근** | 맥미니 도커에서 repo clone (이벤트리서치와 동일 패턴 — 260724 결정 #2·#3) |

> **현재 `github.com/Giana0412/obsidian-vault`는 김규형 개인 테스트용이며 정식 레포가 아니다.**
> 전사 도입 시 **회사용 레포를 별도로 신설**하고 내용을 옮긴다. → §12-1

## 3. 콘텐츠 범위 — What goes in / stays out

### 판정 규칙 [제안]

**질문은 하나뿐이다. "확정됐는가"는 판단 기준이 아니다.**

> **이 문서는 코드가 바뀌면 같이 바뀌어야 하나?**
> → **YES** = 모노레포 `docs/` (기능 명세, API 설계, 개발 규칙, QA)
> → **NO**  = **vault** (회의, 결정, 세일즈, 파트너십, 브랜드 — 확정돼도 계속 vault)

"왜 그렇게 정했는지"는 코드가 열 번 바뀌어도 그대로 유효하다. 그래서 vault에 남는다.

### 경계선

| | **들어감 (vault)** | **남김** |
|---|---|---|
| **회의** | 전사본 · 정리본 · 결정사항 3종 | — |
| **세일즈** | 파트너별 딜 맥락, 공 소재, 막힌 이유 | 계약 원본·고객 개인정보 → **Drive** |
| **개발** | "왜 멈췄는지" 맥락, 미해결 질문, 결정 이력 | `features/`(85) `guides/`(16) `qa/` `ir/`(334) → **모노레포 git** |
| **바이너리** | ❌ **md만** | pdf·이미지·덱·녹음 원본 → **Drive** (링크만 vault에) |
| **개인 데이터** | ❌ | `personal/` 로컬 전용 repo (히스토리까지 분리 완료, 2026-08-06) |

바이너리 배제는 260803 정리본 2-9의 결정을 따른 것이다 — *"옵시디언에는 MD 파일만
들어가야 하므로 원본은 드라이브와 오간다."*

### 메모 무덤을 막는 장치

기획서 **배드 시나리오 2번**: *"vault만 만들고 승격 루틴이 없으면 그냥 메모 무덤이 됨.
문서가 한 곳 더 늘어날 뿐."*

이 경고에 대한 답은 **"확정되면 다른 데로 옮긴다"가 아니다.**
옮기는 건 파편화를 되살릴 뿐이고, 기억 창고를 만들겠다는 목적과 정면으로 어긋난다.
무덤이 되는 걸 막는 건 **기록이 실제로 쓰이는가**이며, 장치는 셋이다.

| # | 장치 | 상태 |
|---|---|---|
| 1 | **결정 → 행동** — 액션아이템을 자동 감지해 Slack 기한 문의 → 캘린더 등록 → 당일 알림 | ⚠️ 구현·검증 완료, 현재 입력 끊김 |
| 2 | **기록 → 답변** — 에이전트가 "그거 왜 그렇게 했죠?"에 vault를 근거로 답한다 | 🟠 데모 1회, 헤르메스 연결 미구현 |
| 3 | **오래된 문서 정리** — `review_by` 기준 월 1회 점검 (§5) | 🟠 규칙만 수립 |

**2번이 이 프로젝트의 본질이다.** 기억이 실제로 조회되면 살아 있는 창고고,
아무도(사람도 에이전트도) 안 꺼내 보면 무덤이다.

### 승격 — 좁게 정의한다

승격은 "확정된 문서의 이사"가 아니라, **vault의 결정이 코드 사양으로 바뀔 때 파생되는 문서**를
모노레포에 만드는 일이다.

```
vault/06-docs/03-결정사항/260803-....md      ← 결정문. 영구히 vault에 남는다
        │
        │ 이 결정이 코드로 구현되어야 한다면
        ▼
monorepo docs/features/260810-....md          ← 파생된 기능 명세. 코드 옆에 산다
        │
        └─ vault 원문에 promoted_to 역링크만 추가 (원문은 이동하지 않음)
```

예: 260803 결정 #4 *"TC를 별도 문서로 작성한다"* → 결정문은 vault에 남고,
실제 TC 문서는 코드와 함께 움직이므로 모노레포로 간다.

**따라서 승격 건수가 적은 것은 정상이다.** 회의 결정 대부분은 코드 사양이 아니라
맥락이고, 맥락은 vault에 남는 것이 맞다. 이 루틴은 `promote` 스킬로 구현했다 (§5).

### `08-sales/pipelines/{파트너}.md` [제안]

기획서가 제안했으나 아직 구현되지 않은 부분. 고정 필드:

```yaml
---
partner: 채널A
ball: our | their            # 지금 공이 누구에게 있는지
last_contact: 2026-08-10
next_action: 견적서 발송
block_reason: 예산 확정 대기   # 막혀 있으면
event_d_day: D-73             # 연결된 이벤트가 있으면
---
```

지호님 미팅(260710) 결정 #3의 **"대회 날짜 기준 영업 시점 알림(D-90/D-80)"** 이
붙을 자리가 정확히 여기다. 단, **영업 단계별 기한 수치가 아직 미확정**이다
(박지호 ↔ 이상욱 논의 예정 건). → §12-4

### 태그 정책 [제안]

**태그는 최소로.** 분류는 이미 폴더가 하고 있으므로, 태그는 **상태만** 표시한다.

```
#결정됨   #미결   #폐기
```

태그를 분류에 쓰기 시작하면 폴더와 이중 관리가 되고, 사람마다 다르게 붙여 곧 무너진다.

### 링크 정책

- **상호링크는 적극적으로.** 3종 문서는 서로를 반드시 링크한다 (이미 관행화됨)
- 형식: `[[../01-전사본/260803-...|전사본]]`
- 승격된 문서는 frontmatter에 `promoted_to` / `promoted_pr` / `promoted_at`

### frontmatter 표준 [제안]

지금 파일마다 제각각이다. 아래로 통일한다.

```yaml
created:    2026-08-10      # 필수
회의일:      2026-08-03      # 회의 문서면 필수 (created와 다를 수 있음)
참석자:      김규형, 이준범
source_url:                 # Drive/Slack 원본이 정본이면 그 링크
status:     확정 | 진행중 | 보류 | 폐기
```

> launchd는 앱과 무관해서 매시간 정상 실행되지만, 입력이 끊겨 "처리할 새 원본 없음"만
> 반복하고 있다. 로그만 보면 정상으로 보이는 것이 이 상태의 위험한 점이다.

### 스킬 3종 (오늘 구현, 커밋 배포됨)

| 스킬 | 한 마디 | 하는 일 |
|---|---|---|
| `handoff` | "다 썼어, 넘겨줘" | 종류 판별 → 템플릿 정리 → 중복 확인 후 저장 → 즉시 동기화 → 보고 |
| `resolve-conflict` | "충돌 났어, 풀어줘" | 백업 → 진단 → 유형별 해소 → 마커 검증 → 동기화 |
| `promote` | "이건 코드로 만들어야 해" | 파생 명세 작성 → 구조 가드 6개 검증 → PR(자동머지 X) → vault 역링크. **원문은 vault에 그대로 둔다** |

**세 스킬 공통 원칙: 결과 보고에 git 용어를 쓰지 않는다.**
"커밋/푸시/브랜치" 대신 "저장했습니다 / 팀에 공유됐습니다".
결정 #10의 목적이 개념 학습 제거이므로, 에러 메시지에서 그게 새어나가면 의미가 없다.

## 6. 동기화 / 백엔드

**[결정됨]** GitHub로 간다. 단, 비개발자가 커밋/PR/푸시 개념 없이 쓸 수 있도록
자동화 스킬을 전제로 한다. — 260803 결정 #10
Obsidian Sync 연간 결제는 하지 않는다 (1년 내 유행이 지날 수 있다는 이유).

### 동기화 주체 — 플러그인이 아니라 **Orca + Claude Code**

```
   사람: "이거 넘겨줘"  /  "최신으로 받아줘"
                │
        Orca + Claude Code          ← 여기가 동기화 엔진
                │  pull → 정리·저장 → commit → push
                ▼
          GitHub (회사 레포)
                │
                ▼
        각자의 Obsidian (읽기)
```

**팀원은 git 클라이언트도, 옵시디언 플러그인도 설치하지 않는다.**
Orca에 말하면 Claude Code가 pull·push를 대신한다.
사람이 마주치는 개념은 **"넘겨줘"와 "받아줘" 두 개뿐**이다.

### 브랜치 전략 [제안 → 채택]

애초 논의는 "모든 저장을 PR→자동머지"였으나, **자동 머지되는 PR은 리뷰 게이트 역할을
하지 못하면서 실패 지점만 늘린다.** 실질을 따져 2단으로 나눈다.

| 대상 | 방식 | 이유 |
|---|---|---|
| **vault 일상 저장** (회의록·세일즈·노트) | **main 직접** (`handoff` 스킬이 push) | md는 파일 단위 충돌이 드물다. 리뷰할 대상도 아니다 |
| **모노레포 승격** | **브랜치 → PR → 사람 리뷰** | 코드 레포이고 여기서는 리뷰가 실제 게이트 |

결정 #10의 목적("비개발자가 개념 없이 쓴다")은 `handoff` 스킬로 충족된다.

### 자동화 머신의 자동 백업 설정 (`.obsidian/plugins/obsidian-git/data.json`)

vault 원본이 있는 **자동화 머신 한 대에만** 적용한다 (맥미니 이전 예정, 현재는 노트북).
스킬을 안 거친 변경(자동화 스크립트 산출물 등)도 유실되지 않게 하는 안전망이다.

```json
"autoSaveInterval": 10,     // 10분마다 자동 저장
"autoPushInterval": 10,     // 10분마다 GitHub 반영   ← 8/10 수정 (0이었음)
"autoPullInterval": 10,     // 10분마다 남의 변경 수신 ← 8/10 수정 (0이었음)
"autoPullOnBoot":  true,
"pullBeforePush":  true,
"syncMethod":      "merge"
```

> **수정 배경**: `autoPushInterval: 0` 이라 커밋만 쌓이고 원격에 안 올라가
> **미푸시 11커밋**이 누적돼 있었다. 원본 머신인데 원본이 공유가 안 되는 상태였다.
> pull도 함께 켠 이유는 자동화 파이프라인이 남의 변경 위에서 돌아야 하기 때문이다.
>
> **다만 이 플러그인은 Obsidian 앱이 떠 있어야만 돈다.** 앱이 꺼져 있으면 설정과
> 무관하게 아무것도 반영되지 않는다 — 실제로 8/9 10:47 이후 자동 커밋이 0건이다.
> 근본 해결책은 스크립트가 직접 커밋하게 만드는 것이다
> ([[../01-architecture/자동화-동작구조]] §9).

### 충돌 처리

1. `pullBeforePush` + `syncMethod: merge` 로 대부분 자동 해결
2. 같은 파일 동시 편집 시 conflict marker가 남는데 **비개발자는 이걸 못 푼다**
   → `resolve-conflict` 스킬이 처리
3. **스킬의 안전장치가 이 설계에서 가장 중요한 부분이다.** AI가 충돌을 대신 푸는 구조에서
   진짜 위험은 충돌이 아니라 **AI가 판단해서 한쪽을 지우는 것**이다. 그래서 금지 명령을 명시했다:
   `reset --hard` / `checkout --ours|--theirs` / `push --force` / `clean -fd`
   지식 문서는 **양쪽 보존이 언제나 기본값**이고, 같은 줄이 충돌하면 두 버전을 나란히 남긴다:

   ```md
   <!-- ⚠️ 두 분이 같은 부분을 다르게 적었습니다. 맞는 쪽만 남기고 이 주석을 지워주세요. -->
   - (A안 / 규형) 완성도 기준은 공식 사이트까지
   - (B안 / 준범) 완성도 기준은 공식 사이트 + 기사
   ```
4. 작업 전 `backup/conflict-<날짜시각>` 브랜치로 박제. 사람 확인이 남으면 백업을 지우지 않는다.
5. **예방**: 세일즈 파이프라인은 파트너당 1파일로 쪼개 동시 편집 자체를 줄인다.

### 팀원 PC에 필요한 것 — 정확히

플러그인은 필요 없지만 **"아무것도 안 깔아도 된다"는 사실이 아니다.**

| 준비물 | 필요 여부 | 비고 |
|---|---|---|
| Obsidian | **필수** | 읽고 찾는 용도 |
| Orca IDE | **필수** | 쓰기 진입점 — 260724 결정 #7 |
| Claude Code CLI | **필수** | **회사 계정 좌석 필요** (260724: "Claude CLI 설치, 상무님 계정 수령") |
| git | 불필요 | macOS 기본 제공(`/usr/bin/git`). 첫 실행 시 Xcode CLT 설치 프롬프트가 뜰 수 있음 |
| GitHub 인증 | **필수** | `osxkeychain` 또는 `gh auth login` — **사람마다 1회** |
| 레포 clone | **최초 1회** | 안내 또는 대행 필요 |
| **옵시디언 플러그인** | **불필요 (0개)** | ← 이 설계로 실제로 없어진 부분 |

**없어진 것은 "플러그인 설치·설정" 한 겹이지 온보딩 전체가 아니다.**
Claude 계정 좌석과 GitHub 인증은 사람마다 남아 있고, 이게 전사 도입에서 가장 잘 깨지는 구간이다.
→ 계정 좌석은 §12-6, 온보딩 절차는 §11 블로커 6번

### 레포 위생 (8/10 처리 완료)

전사 도입 전 반드시 정리해야 했던 부분. **추적 파일 2,583개 → 68개.**

### 연동 현황

| 대상 | 상태 | 내용 |
|---|---|---|
| **Slack** | ⚠️ 수집 멈춤 | STAGE2 기한 문의·알림은 정상. **수집(slack-sync)이 8/6 이후 멈춰 있다** (`autoSync: false`). 토큰은 `curl -K` 파일로만 다뤄 에이전트에 노출 안 됨 |
| **GitHub** | ✅ | **Orca + Claude Code가 push/pull 주체.** 자동화 머신의 obsidian-git은 보조(현재 멈춤). `promote` 스킬이 모노레포 PR |
| **Google Calendar** | ✅ | 회사 캘린더(`gkimam@oao-corp.com`) 하드코딩. 개인 계정은 별도 MCP로 분리 |
| **Google Drive / Gmail** | ✅ | 원본 참조, 뉴스레터 아카이브 |
| **AWS** | ❌ 미연결 | 다이어그램상 예정 |
| **헤르메스 / Symba** | ❌ 미구현 | vault를 읽는 경로가 아직 없다 |

### 캘린더 계정 분리 — 사고 후 방어

회사 결정사항의 액션아이템이 개인 캘린더로 잘못 등록된 사고(8/6)가 있었다.
재발 방지로 STAGE2에 회사 캘린더 ID를 하드코딩하고, allowedTools에 회사 계정 도구만 남겼다.
**회사/개인은 절대 섞지 않는다**는 것이 이 vault 구조 전체를 관통하는 원칙이다
(`personal/` 분리도 같은 원칙의 산물).

### AI 워크플로우 연동 — 두 가지 제안

**(1) 메모리 계층 정리 [제안]**

기획서가 인용한 원칙을 적용한다:
> *"human notes = source, agent notes = 별도 레이어"*, `memory_queue → 사람 승인 → wiki 승격`

```
vault           = 정본 (사람이 승인한 것)
.omc/ notepad   = 휘발성 캐시 (git 추적 안 함 — 8/10 처리)
05-slack/       = 에이전트 수집 레이어 (사람이 손대지 않음)
06-docs/        = 사람이 읽는 결과물
```

`07-persona/`가 이미 좋은 선례다 — 회사용 페르소나가 `personal/`을 단 한 줄도
참조하지 않도록 설계했고, 그래서 회사 봇에 개인 데이터가 샐 경로가 없다.

**(2) 헤르메스 → vault 읽기 경로 [제안]**

이벤트리서치와 같은 패턴이 자연스럽다:
맥미니 도커가 vault repo를 clone/pull → 컨테이너 안에서 **read-only** 참조.
(260724 결정 #2·#3 — "맥미니는 실행 전용, 도커 안에서만")

### ⚠️ 다이어그램에 대한 주의

Obsidian 아래에 MCP를 두고 외부 시스템을 vault가 직접 물게 하면,
**vault가 "메모리"를 넘어 "메모리 + I/O 게이트웨이"가 된다.** MCP 연결이 늘수록
vault가 SSOT처럼 보이기 시작하고, 이는 **배드 시나리오 1번이 열리는 지점**이다.

선을 미리 그어두기를 제안한다: **"vault는 MCP로 읽되, 쓰기는 md로만."**

## 9. 플러그인 / 커스터마이징 정책

### 대원칙 [제안]

> **"Obsidian 없이 Claude와 git만으로도 온전히 읽히는 vault를 유지한다."**

이 vault의 자산은 플레인 마크다운이다. 파일을 특정 플러그인 없이는 못 읽게 만드는 순간,
**에이전트 메모리 레이어라는 목적 자체가 무너진다.**

### 허용 범위

| 구분 | 대상 | 정책 |
|---|---|---|
| **팀원 필수 플러그인** | **없음 (0개)** | 동기화는 Orca + Claude Code가 한다. 단, 플러그인이 없을 뿐 **앱·계정·인증은 필요하다** — §6 표 참조 |
| **자동화 머신만** | `obsidian-git`, `slack-sync` | 자동 백업·수집용. 한 대에서만 돌면 된다. **단 앱이 상시 실행돼야 하는 제약이 있어, 스크립트로 대체하면 전사 0개가 된다** |
| **개인 자유** (gitignore) | 테마, `Claudian`, 창 배치, 에디터 취향 | 각자 |
| **금지** | Dataview 인라인 필드, Templater 스크립트 등 **파일 내용을 플러그인 종속으로 만드는 것** | 플레인 md 원칙 위반 |
| **정리 대상** | `slack-sync` | 260803 결정 #12로 Orca 직접 방식에 밀려 후순위. **자체 패치본**이라 유지보수 부담 + 토큰을 로컬 저장 |

### 팀원 각자 세팅 vs 공유 통일 — **옵시디언 안에서는 통일할 게 없다**

동기화를 플러그인이 아니라 Claude Code가 맡으므로, **옵시디언 쪽에서 맞춰야 할 설정이
없다.** 테마·창 배치·단축키는 전부 자유다.

**다만 온보딩이 없어지는 것은 아니다.** 없어진 것은 플러그인 설치·설정 한 겹이고,
**Claude 계정 좌석과 GitHub 인증은 사람마다 그대로 남는다** (§6 표).
전사 도입에서 가장 잘 깨지는 구간은 여전히 여기다.

반대로 `workspace.json`처럼 개인 취향인 것을 공유하면 상시 충돌원이 된다
(실제로 커밋되고 있었고 8/10에 제외 처리했다).

## 10. 성공 기준

기획서가 **실패 조건을 먼저 명시**했으므로, 성공 기준은 그것을 뒤집어 잡는다.

### 🔴 실패 판정 — 하나라도 해당하면 실패

1. 같은 문서가 vault와 `/oao/docs` 양쪽에 생겨 **어느 쪽이 최신인지 헷갈리는 상태**가 발생
2. 문서는 쌓이는데 **아무도 꺼내 보지 않음** — 사람도, 에이전트도. 메모 무덤
3. 비개발자가 결국 안 쓰고 Slack·구두로 돌아감

### 📊 정량 지표 — 8/14 전사 도입 후 **2주 시점(~8/28) 판정**

| # | 지표 | 목표 | 현재 |
|---|---|---|---|
| 1 | 회의 후 24h 내 결정사항 문서화율 | 90%+ | 파이프라인 가동 중 |
| 2 | **조회율** — vault 문서가 실제로 참조된 횟수 (에이전트 인용 + 사람 열람) | 주 5회 이상 | 측정 수단 미비 🟠 |
| 3 | 비개발자 자립 — Orca에 "넘겨줘"만으로 저장 성공 (개발자 개입 0) | 주 1회 이상 × 3명 | 0 |
| 4 | 미푸시 커밋 | 상시 0 | ✅ 0 (8/10 해소, 11→0) |
| 5 | `docs/meetings` 공백 재발 | 2주 이상 공백 0회 | 7주 공백 이력 |
| 6 | `questions.md` 해소율 | 신규 유입 ≤ 해소 | 30+ 누적, 해소 0 |
| 7 | 에이전트 인용 — "그거 왜 그렇게 했죠?"에 vault 근거로 답변 | 성공 | 8/7 데모 1회 성공 |

**지표 2번과 7번이 가장 중요하다.** 쌓이는 양이 아니라 **꺼내 쓰이는지**가 성패를 가른다.
나머지가 다 좋아도 아무도 조회하지 않으면 무덤이다.

> 조회율은 현재 **측정 수단이 없다.** 헤르메스가 vault를 읽기 시작하면 그 호출 로그가
> 자연스러운 계측 지점이 된다 (§8). 그전까지는 지표 7(에이전트 인용 성공)로 대신 본다.

### 🎯 정성 기준 — 한 문장

> **"같은 설명을 두 번 하지 않게 되었는가."**
>
> 이상욱이 *"이거 하셨어요?"* 라고 묻지 않아도 상태를 알 수 있는가.
> 이것이 260803 회의에서 제시한 원래 동기다.

## 12. 결정이 필요한 것 (혼자 정할 수 없는 항목)

### 12-1. 회사 레포 신설 — 🟠 작업 (방향은 확정)

**[결정됨]** 현재 `github.com/Giana0412/obsidian-vault`는 김규형 개인 테스트용이며,
전사 도입 시 **회사용 레포를 따로 판다.**

남은 것은 실행 세부뿐이다.

- 레포 이름 (`oao-wiki` 로 갈지)
- 초기 권한을 줄 대상 (이상욱 / 이준범 / 박지호 / 그 외)

> 테스트 레포의 내용은 그대로 옮길 수 있다. 다만 `.git` 히스토리에 초기
> 시행착오와 `.omc` 잔재가 남아 있으므로, **히스토리 없이 현재 상태만 새 레포에
> 올리는 쪽**을 권한다 (깨끗하게 시작 + 21MB 군더더기 제거).

### 12-2. Notion 폐기 확정 — 🔴 도입 전 필수

8/3 결정 #9는 "노션은 아예 쓰지 않는 방향"이지만, 7/31 강의 후속으로
**영업 DB의 노션 전환 검토 6개 항목**이 미정 상태로 살아 있다.

- 노션을 완전히 접는가? 세일즈 DB만 예외로 두는가?
- 접는다면 **세일즈에 언제·누가 알리는가?**

> **의견**: 둘 다 살려두면 세일즈가 어디에 쓸지 모른다. 명시적으로 하나를 접어야 한다.

작업은 하루면 끝나며, **승인만 필요**하다.

### 12-4. 세일즈 파이프라인 필드 확정 — 🟡

### 12-5. 팀원 Claude 계정 좌석 — 🔴 도입 전 필수

**이 설계는 쓰는 사람 전원에게 Claude Code 계정이 있어야 성립한다.**
사람의 쓰기 경로가 Orca + Claude Code 하나이기 때문이다(§2).

- 세일즈·운영 인원까지 좌석을 확보하는가? 몇 석이 필요한가?

> 이 항목이 해결되지 않으면 §10 지표 3번(비개발자 자립 쓰기)은 구조적으로 달성 불가다.

### 12-7. 별건 — 모노레포 자격증명 노출 🔴
